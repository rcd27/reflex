# Сертификация калитки

Устройство, на котором проверяется, что заявленная способность бэкенда **делается**, а не только
объявлена.

Типы к этому дню убрали пустые заявления: сказать «умею вводить», не назвав, как инъекция
становится командой стока, нельзя — [`CanInject`](../../../core/src/capability.rs) несёт метод.
Осталось ложное: команда построена, `emit` ответил `Ok`, а на провод ничего не вышло. Типом это
невыразимо по построению, потому что происходит за их границей.

## Прогон

```sh
docker compose up -d --build
docker exec certify-dut certify eth0 /shared/far.pcap <нонс>
```

Ответ — строка JSON и код возврата:

| Код | Вердикт | Что значит |
|-----|---------|------------|
| 0 | `held` | нонс найден у свидетеля: калитка вводит |
| 1 | `broken` | свидетель работал, чужие кадры видел, нашего нет |
| 2 | `invalid` | **вердикта нет**: свидетель молчал или запись не читается |

Третья строка — не оттенок второй. «Прибор не работал» и «подопытный солгал» дают один и тот же
пустой результат, и слить их значило бы объявлять нарушение всякий раз, когда сломался стенд.

## Устройство

```
witness ──dumpcap──▶ /shared/far.pcap ──▶ dut ──вердикт──▶ JSON
   eth0                общий том          reflex_core::pcap + certify::injects
```

**Свидетель в чужом сетевом пространстве** — не церемония. Стой он рядом с подопытным, он заверял
бы «кадр дошёл до точки съёма ядра», а не «кадр дошёл».

**Вердикт в коде, а не в оболочке.** Прежний стенд (`tests/e2e/run-e2e.sh`, снят) судил по коду
возврата фонового бинаря: наблюдение шло в контейнере, утверждение на хосте, связь между ними была
честным словом.

**Образ минимален намеренно** — это отрицательное свидетельство. В нём нет ни `nft`, ни
`iproute2`, ни загрузчика eBPF; закон держится, значит `AfPacketBackend` не опирается на них
тайком. На машине разработчика этого не установить: там есть всё.

## Что здесь названо и не закрыто

* **Свидетель не вполне независим.** На Linux libpcap работает через тот же `PF_PACKET`, что и
  `AfPacketBackend`: дефект самого механизма ядра оба увидят одинаково. Второй прибор иной природы
  (счётчики `/proc/net/dev`) — следующий срез. Канон заимствования свидетеля по пяти осям
  опубликован в #326.
* **Контейнер делит ядро с хозяином.** Минимальность образа доказывает отсутствие ИНСТРУМЕНТОВ, но
  не отсутствие возможностей ядра: модуль, загруженный снаружи, виден изнутри. Отрицательный
  preflight внутри устройства — следующий срез.
* **Сертифицирован один закон из пяти.** `CanObserve`, `CanDrop`, `CanModify`, `CanHold` ждут
  своих; `TcAfPacketBackend` требует образа с загрузчиком eBPF.

## Чем это НЕ является

Частью потока доставки продукта (`docs/E2E-FLOW.md`). Тот описывает путь «ключ → невод»; здесь
проверяется фундамент, и у него свой предмет — работает ли калитка, а не что делает противник.
