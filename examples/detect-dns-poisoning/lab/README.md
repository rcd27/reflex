# Стенд: боевая верификация `detect-dns-poisoning`

Отравление DNS на **реальном ТСПУ вантажа**: на запрос заблокированного домена инжектится
поддельный ответ (`NXDOMAIN`/пустой) вместо адреса. Первый use-case на транспорте `Udp` — движок
смотрит UDP:53, а не TCP (полиморфизм `.from`).

## Что доказывается

```
[reflex] подозрение на отравление DNS: nnmclub.to (инжект NXDOMAIN/пустой ответ)
[итог] ЗЕЛЕНО: отравление DNS «nnmclub.to» поймано на боевом трафике; «vk.com» чист
```

- `TARGET` (`nnmclub.to`) — стабильный инжект NXDOMAIN @8.8.8.8 (домен существует, `@1.1.1.1` даёт
  адрес — расхождение резолверов подтверждает инжект).
- `CONTROL` (`vk.com`) — настоящий ответ, отравление не срабатывает.

`DnsPoisonInstrument` читает разобранное DNS-сообщение (`core::dns::DnsMessage`), а не байты — через
`.from(Udp)` движок кормит его словарём UDP. Имя цели — из самого DNS-запроса.

## Оговорки

- **Подозрение, не приговор.** Легитимный `NXDOMAIN` (несуществующее имя) даёт то же. Точный
  признак — кросс-резолвер, но это активная проба (у потребителя).
- ТСПУ недетерминирован; цель может «выздороветь». Пара `nnmclub.to`/`vk.com` устойчива на замерах.

## Запуск

```sh
sh verify.sh
```

Требует Docker, `NET_ADMIN`, `nfnetlink_queue`, вантаж за ТСПУ.
