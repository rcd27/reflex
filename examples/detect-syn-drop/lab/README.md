# Стенд: боевая верификация `detect-syn-drop`

IP-blackhole на **реальном ТСПУ вантажа**: `SYN` к цели роняется по адресу, `SYN+ACK` не приходит,
клиент повторяет `SYN`. Отдельный феномен — отдельный пайп: через `SilentBlock` (тихий дроп после
рукопожатия) это не выразить, там соединение уже открыто.

## Что доказывается

```
[reflex] IP-blackhole: 149.154.167.50 (SYN без ответа, повтор через 1024мс)
[итог] ЗЕЛЕНО: IP-blackhole «149.154.167.50» пойман по адресу на боевом трафике; «vk.com» чист
```

- `TARGET` — IP датацентра Телеграма: SYN-дроп по адресу, **имени нет** (нет `ClientHello`). Цель
  опознаётся ПО АДРЕСУ — доказательство fallback `extract(Sni)` на боевом трафике.
- `CONTROL` (`vk.com`) — рукопожатие проходит, blackhole не срабатывает.

`SynDropInstrument` читает `SeenTcp` (`Syn`/`Handshaken`), а не `Seen` — в дверь `.detect()` он
встаёт через `Reads<Reading>`: фасад кормит широким словарём провода, прибор сужает до своего.

## Запуск

```sh
sh verify.sh
```

Требует Docker, `NET_ADMIN`, модуль `nfnetlink_queue` и **вантаж за ТСПУ** (иначе SYN не роняется).

## Оговорки

- ТСПУ недетерминирован; IP датацентров Телеграма меняются. Подбери свой `TARGET`/`CONTROL` под
  вантаж в `compose.yml`.
- Стенд проверяет проводку прибора против реального дефекта, не реализм цензуры.
