# Один носитель: снос `category` и `Reactor`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оставить `core::step::Step` единственным носителем машины Мили, убрав из репы стадийную категорию над потоком, диалект реактора и всё, что на нём стояло.

**Architecture:** Почти чистое удаление. Одна задача не удаляет: `category::from_source` сводится с уже существующим дублем `certify::observation::watching` в одну дверь, чтобы проверка `CanObserve` компилятором не уехала в модуль законов. Остальные три — снос: драйверы внешней петли, `Reactor` со свитой, `category` со стадиями.

**Tech Stack:** Rust 2021, без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-09-06-alphabet-and-absorption-design.md`, §3 «Впитывание: одна идея — одна запись».

## Правило, по которому этот план сносит

> **Код живёт в дереве, знание — в истории.** Сохранять форму «вдруг пригодится» — значит держать в рабочем наборе то, что никто не ест, и платить за это каждым чтением.

Репа так уже рассуждала при переезде движка: «история осталась в суперпроекте; переезд между репозиториями её не переносит, и притворяться, будто переносит, незачем».

Поэтому **ничего не переносится ради сохранности**. Что нужно — вернётся написанным заново и правильно; что не вернулось — не было нужно.

## Что этот план НЕ делает

- **`Detector` не трогается** — 29 реализаций в `src`, восемь комбинаторов, `detect_per`. Отдельный план (2B), крупнее настоящего. Это разделение по роду работы (переписывание реализаций против удаления модулей), а не осторожность.
- **`Tap` не сносится** — его последний потребитель `NfqPipeline::with_tap` умрёт вместе с фасадом в плане 3.
- **Алфавит не расширяется** — план 3.

## Три названные потери

Названы, чтобы не быть молчаливыми. Не для того, чтобы их оплакивать.

| уходит | что предъявляло | когда вернётся |
|---|---|---|
| `category::Injection` | типом: «оператор после инъектора» невозможен | план 3, **сильнее**: инъекция перестаёт быть морфизмом цепочки вовсе |
| `the_same_chain_runs_over_two_different_backends` | переносимость цепочки между бэкендами (третий vision §3.2) | план 3: цепочка есть значение, бэкенды суть драйверы |
| `expand_effects` / `drive_owned` | форму ВНЕШНЕЙ петли: «решил → сделал IO → увидел исход → решил» | §7.4 спеки, **с гвардом** — которого у них нет |

Третья — главная, и рассуждение по ней записано здесь, потому что первое чувство было противоположным.

Обе конструкции суть анаморфизм (`futures::stream::unfold`) с обратной подачей: эффект уходит в async-край, край возвращает событие, событие идёт обратно в машину, пока не выйдет терминал. Форма нетривиальная и правильная.

**И всё же сносятся.** Потребителей вне собственных тестов ноль — то есть свидетельствует о них только подопытный. Гварда у петли нет, а по сегодняшнему дизайну негвардированная внешняя петля есть **неправильная** петля: сохранить её значит оставить доступной в неправильном виде. Когда §7.4 назовёт окно оседания, петля перепишется с ним — то есть перенос сейчас есть перенос дважды.

Знание о форме уходит в сообщение коммита, код — в историю.

## Прибор: `grep` здесь НЕ GNU grep

Установлено на прогоне задачи 2. В этой оболочке `grep` — функция-обёртка над `ugrep`
(`--ignore-files --hidden -I`), и у неё два свойства, которых у GNU grep нет:

* **пути печатаются БЕЗ `./`** — значит фильтры вида `grep -v "^./путь"` не срабатывают
  вовсе и молча пропускают всё;
* **уважается `.gitignore`** — `target/` исключается им, а не фильтром.

Все фильтры в этом плане переписаны на подстроку без якоря (`grep -v "путь"`), потому что
такая работает под обоими. Если проверочный `grep` вернул больше, чем ожидает шаг, —
**сперва проверь, не пустышка ли фильтр**, и лишь потом докладывай о потребителях.
