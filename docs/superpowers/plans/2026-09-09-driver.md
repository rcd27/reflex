# Драйвер: один функтор и переигрываемая лента — план работ

> **Исполнителю:** задачи по одной, гейт между ними держит хранитель (эта сессия).
> Шаги — чекбоксами. Дисциплина гейта — в «Общих ограничениях», она включена в КАЖДУЮ
> задачу: тест обязан уметь упасть (мутация роняет), константы замером, докблок причиной,
> провенанс историей (`git log -S`), не догадкой.

**Цель:** замкнуть носитель движка — один функтор `акт → слово носителя через способность`
(§9.4) и переигрываемая лента из трёх источников (`Packet | Tick | Answer`), на которой
садится восьмой закон `replays` (§12.3).

**Архитектура:** машина остаётся чистой коалгеброй (§1, §2) — шаг на каждой букве, мир
внутрь не входит. Драйвер есть функтор из мира буквы в мир носителя (§9): сливает три
асинхронных источника в одну упорядоченную ленту (недетерминизм замерзает здесь), несёт
акт в вердикт через способность, и в режиме `replay` пере-подаёт ленту, глуша сайд-эффекты.
Спуск слова вниз к `Act` пакета уже построен (§5 `Descends`); строим носитель, не алгебру.

**Стек:** Rust, `reflex-core` (коалгебра, `interleave` §8, `capability`, `serves`),
`reflex-engine-nfq` (боевой носитель), `reflex-linux` (`QueueSocket`).

**Спека:** `docs/superpowers/specs/2026-09-09-driver-design.md` — план спорит из неё, читать обе.

## Общие ограничения

- **Тест обязан уметь упасть.** Перед сдачей задачи сломать проверяемое место, убедиться,
  что тест краснеет; для `compile_fail` — показать ТЕКСТ ошибки. Мутация каждой ветки роняет
  ≥1 тест. (Память проекта: зелёный на сломанном коде хуже отсутствующего.)
- **Замер прогоном, не грепом/догадкой.** Числа и провенанс — прогоном и `git log -S`.
- **`cargo test --workspace` зелёный, `cargo build --workspace` без предупреждений** на сдаче.
- **Границы предмета (спека):** знание контура у нас не живёт (`Answer<C>` — содержимое
  потребителя); фреймворк называет копредел/акт, не угрозу.
- **Машина не встаёт.** Ни в одной задаче нет блокирующего ожидания в шаге — ожидание есть
  ФАЗА машины (состояние), доставку буквы держит драйвер. Блок = не-шаг Мили, ломает `replays`.

## Task 1: буква `Answer` — рукав алфавита ЛЕНТЫ, не вариант прибора (§8 + §4)

> **Правка от находки исполнителя.** `Answer` вариантом `DetectorEvent` тянул 18 приборов,
> каждый с веткой «не моя буква» — запах, что буква не их. `Answer` есть буква ЛЕНТЫ (драйвера),
> прибор её не читает по умолчанию; доходит адресату §4-сужением. Приборы НЕ трогаются.

**Files:**
- Create/Modify: тип алфавита ЛЕНТЫ `TapeLetter<T,C> = Event(DetectorEvent<T>) | Answer(Answer<C>)`
  (в `core`, рядом с `detector`/`serves`; имя на усмотрение)
- Modify: `core/src/interleave.rs` (+`answered`, кладёт в алфавит ленты)
- **НЕ трогать** `DetectorEvent` в `core/src/detector.rs` — три буквы прибора остаются
- Test: порядок (interleave) + сужение (прибор, не читающий `Answer`, его НЕ получает — без ветки)

**Interfaces:**
- Produces: `Answer<C> { input: C, at: Instant }` — ОТДЕЛЬНЫЙ тип, не вариант `DetectorEvent`;
  `TapeLetter<T,C>` — алфавит ленты; `Interleave::answered<T,C>(self, input: C, at: Instant)
  -> (Self, Vec<TapeLetter<T,C>>)` — узлы сетки до `at`, затем `Answer`; порядок держит та же
  конструкция, что `saw` (не проверка в тесте — конструкция).
- Consumes: `Reads` (§4) — сужение алфавита ленты к алфавиту прибора.

- [ ] **Шаг 1. Провальный тест (порядок И адресность).** (1) `saw` в `t1`, `answered` в `t2>t1`,
  `idle` в `t3>t2` — буквы ленты идут по неубывающему `at`, тики сетки между ними. (2) Прибор,
  читающий только `DetectorEvent<T>`, `Answer` НЕ получает — сужение роняет, БЕЗ ветки «не моё».
- [ ] **Шаг 2.** Прогнать — падает.
- [ ] **Шаг 3.** Ввести `Answer<C>` отдельным типом, `TapeLetter`, `answered` (порядок как `saw`),
  сужение `Reads` алфавита ленты к прибору. **Приборы не трогать** — воркспейс обязан собраться
  без единой ветки «не моё».
- [ ] **Шаг 4.** Прогнать — зелено, `cargo build --workspace` без восемнадцати правок.
- [ ] **Шаг 5. Мутация:** (а) сужение пропускает `Answer` прибору, что его не читает — тест
  адресности краснеет; (б) `answered` кладёт букву без узлов до `at` — тест порядка краснеет.
- [ ] **Шаг 6.** `cargo test --workspace`, `git commit`.

Стоп-условие (если всплывёт): сужение алфавита ленты к прибору не должно потребовать тронуть
`Reads`/`DetectorEvent` шире проекции — если тянет форму шва, остановиться и сказать хранителю.

## Границы плана — чего НЕ делаем

- **Сведение (§12.2)** не строим законом: когда `Answer` спустится к `Act`, где уже прямой
  план, встретятся два спущенных слова — сегодня `unwrap_or_else` «приказ старше плана».
  Назвать законом — на живом примере встречи, отдельной задачей, не в пустоте.
- **Знание контура** не заводим у себя — `Answer<C>` несёт содержимое потребителя.
- **`replays` строится ПОСЛЕ ленты** (Task 6 после Task 5) — он её свидетель; без ленты
  прогонять нечего.

## Открытое (в спеке) — к замеру по дороге

- Форма `Ask` наружу (сокет/канал к контуру) — деталь носителя, рядом с `send`; замерить.
- Стоимость режима `live`/`replay` — не раздваивать горячий путь ветвлением на каждой букве;
  `Replay` — отдельный прогон, не ветка в шаге.
- **§9.1 per-act гейт способности — ОБЯЗАТЕЛЕН ПЕРЕД потребительским `Ask`.** Task 2/3 ввели
  бланкет-баунд `emit<T: CanHold + CanSever + CanAsk>` + заглушку `CanAsk::question->None` у
  `NfqueueBackend`. Это превращает §9.1 «`Ask` не соберётся над носителем без `CanAsk`» в
  рантайм-None: ask-цепочка над носителем-без-контура СОБЕРЁТСЯ и молча зависнет (поток «спросил,
  жду», вопрос ушёл в None). Недостижимо, пока потребитель не спрашивает; достижимо с первым
  потребительским `Ask` (examples-с-Ask). Фикс: строитель цепочки копит баунд per-act (`.ask`
  требует `CanAsk`, не-спрашивающая цепочка — нет), заглушка уходит, компайл-гейт честен. Разнос
  функторов НЕ спасает (баунд убежит за вызов, `act` рантайм). Закрыть ДО examples-с-Ask.
