# Состояние — в IO-край: conntrack как носитель слоя разговора

> Дизайн-документ. 2026-09-09. Опирается на канон
> `docs/vision/2026-09-08-reflex-one-machine-vision.md`.

## Решение

Состояние приборов уезжает из юзерспейса в **conntrack ядра**. Слой
разговора (`Base for Conversation { type Fibre = Flow }`, §4) и слой
conntrack — один и тот же слой, индексированный одной и той же
четвёркой; совпадение не аналогия, а определение. Отсюда:

- ядерный вид разговора (`CtView`) входит **расслоением носителя**:
  `DetectorEvent<(Wire, CtView)>`, сужение — существующими `Reads`/`lmap`;
- следующее состояние — **слово области `Conversation`**, едущее в ядро
  спуском `Packet: Within<Conversation>` вместе с вердиктом;
- юзерспейс становится zero-state: собственное `S` прибора вырождается
  в `()`, то есть машина Мили с единичным состоянием (§1, законно без
  нового имени).

Носителем служит **свой netlink-сокет к `NFNL_SUBSYS_QUEUE`**; крейт
`nfq` с этого пути срезается.

## Что ядро уже считает за нас

Ядро при флаге `NFQA_CFG_F_CONNTRACK` прикладывает к каждому пакету
очереди атрибут `NFQA_CT` (`ctnetlink_glue_build`). Приезжает даром:

| величина | атрибут | чем была бы у нас |
|---|---|---|
| пакеты и байты по направлениям | `CTA_COUNTERS_ORIG/REPLY` | два счётчика на поток |
| возраст потока | `CTA_TIMESTAMP` | момент первого пакета |
| время с последнего пакета | `база(состояние) − CTA_TIMEOUT` | момент последнего |
| TCP-состояние по мнению ядра | `CTA_PROTOINFO` | свой автомат TCP |
| четвёрка, идентификатор | `CTA_TUPLE_ORIG`, `CTA_ID` | ключ таблицы |
| наше состояние | `CTA_MARK` | поле записи таблицы |

`CTA_TIMEOUT` — остаток жизни записи, и `__nf_ct_refresh_acct`
переставляет его на `now + timeouts[state]` при каждом пакете. Значит
«сколько прошло с последнего пакета» — ядерная величина, разрешение
1 с (`nf_ct_expires(ct) / HZ`). База берётся из
`net.netfilter.nf_conntrack_tcp_timeout_*` по состоянию из `CTA_PROTOINFO`.

Обратно из вердикта ядро принимает (`ctnetlink_glue_parse_ct`):
`CTA_MARK`, `CTA_LABELS`, `CTA_STATUS`, `CTA_TIMEOUT`, `CTA_HELP`.

**Чего ядро не даёт:** тишины НАПРАВЛЕНИЯ. Клиент повторяет — `timeout`
освежается, `reply.packets` стоит. Заметить «стоит» нечем, кроме точки
отсчёта; она и есть единственное, что мы кладём в марку сверх фазы.

## Граница: своя дверь к очереди

Крейт `nfq` (в дереве `0.2.5`, опубликован 2022-01-26) на этом пути
срезается. Причина не в возрасте: в `master` апстрима `parse_ct_attr`
разбирает единственный атрибут `CTA_ID`, а сборка вердикта кладёт
`NFQA_VERDICT_HDR | NFQA_MARK | NFQA_PAYLOAD` и не кладёт `NFQA_CT`.
Обе нужные способности лежат непринятыми PR с 2023 года (#14 «mark
conntrack», #17 «try_verdict»). Ждать апстрим — ждать чужую очередь
ревью.

Новый модуль повторяет раскрой, уже оплаченный в `linux/src/conntrack/`:
**IO отдельно, разбор отдельно**, чтобы разбор проверялся без root.

| шаг | сообщение | зачем |
|---|---|---|
| открытие | `NFQNL_MSG_CONFIG` / `CMD_BIND` | привязка к очереди |
| открытие | `CFG_PARAMS` | copy-packet, диапазон |
| открытие | `CFG_FLAGS` / `NFQA_CFG_F_CONNTRACK` | **включает `NFQA_CT`** |
| приём | `NFQNL_MSG_PACKET` | `PACKET_HDR`, `PAYLOAD`, `MARK`, `CT`, `CT_INFO` |
| ответ | `NFQNL_MSG_VERDICT` | `VERDICT_HDR` + `NFQA_CT{CTA_MARK}` |

Атрибуты внутри `NFQA_CT` — те же `CTA_*`, что разбирает
`conntrack/wire.rs`: `attrs`, `tupled`, `counted`, `entry_of`
переиспользуются, меняется только источник тела.

**Закон одного чеканщика.** `CTA_*` разбирает ровно один код —
`conntrack/wire.rs`. Горячий путь обязан пойти через него, а не отрастить
свой разбор той же марки: conntrack — единственный источник истины, и
два разбора одного `CTA_MARK` разошлись бы молча при зелёной сборке.
Дверей к стору может быть сколько угодно; чеканщик буквы — один.

Вместе с крейтом уходит добывание дескриптора разницей множеств
`/proc/self/fd` (`nfqueue/backend.rs`) и вариант `Waited::Blind`:
свой сокет — свой fd.

Приходит на нас то, что крейт делал молча: `ENOBUFS`, несколько
сообщений в одном буфере, GSO-пакеты. Это цена, и она сертифицируется
на стенде, а не тестом.

## Алфавит: расслоение носителя

Носитель `T` в `DetectorEvent<T>` живёт только в варианте `Packet`
(`Tick { node }`, `Opaque { why }` носителя не несут по построению).
Поэтому ct-вид кладётся в носитель:

```
DetectorEvent<(Wire, CtView)>
```

и присутствует ровно там, где есть буква провода — обе половины из
одного `NFQA_CT`-пакета. Ни `Option`, ни отдельного слоя.

Сужение — существующая фибрация §4, не новый комбинатор: прибор провода
проецирует `.0`, ядерный прибор `.1`, смешанный берёт пару. Существующие
приборы остаются объявленными на `Seen`/`SeenTcp`; меняется их `Reads`,
не логика.

Расширение поля внутри `Packet` **отвергнуто**: сузить можно множитель
произведения, но не поле — фибрация сломалась бы.

```
CtView {
    id, tuple: Tuple, orig: Counts, reply: Counts,
    since: CtStamp, idle: CtIdle, tcp: CtProto, state: CtState,
}
```

`Counts` и `Tuple` — существующие типы `conntrack::wire`.

**Доступность привязана к носителю типом, а не проверкой.** `CtView`
входит в широкое слово только у очереди; прибор, читающий ядерный вид,
не соберётся с носителем, у которого такого `impl Reads` нет.
Запрещать нечего — достаточно не давать `impl` там, где ядра нет.

## Слово: состояние адресовано разговору

`NFQA_MARK` — слово о **пакете**: живёт до конца обхода. `CTA_MARK` —
слово о **разговоре**: живёт весь поток. Отсюда `CtState::Of =
Conversation`, и выход прибора

```
Out = (Distress, CtState)        // обе Of = Conversation
```

проходит закон пары (`word.rs:160`: `impl<A: Word, B: Word<Of = A::Of>>`)
без новых сущностей. Вариант с `Of = Packet` закон пары не принимает:
`Distress::Of = Conversation`, а разным областям слиться нельзя.

На край слово едет **спуском** (`Packet: Within<Conversation>`,
`Descends`, §5): состояние принадлежит потоку, но уезжает в ответе на
конкретный пакет, где встречается с вердиктом — и там обе половины уже
`Of = Packet` и склеиваются законом пары в единое ядерное слово,
физически отдаваемое одним `NFQNL_MSG_VERDICT`.

Комментарии баз ложатся на физику: `Packet` — «ждать нельзя: очередь
держит его до ответа»; `Conversation` — «ожидание терпит».

## Кодек марки

```
фаза      3 бита   ничего не сказано / подозреваем / подтвердили / отпустили
оттиск    8 бит    младшие биты reply.packets на момент постановки фазы
тег       4 бита   подпись писателя (константа)
```

Маска — **параметр цепочки**, не константа фреймворка. Фреймворк не
знает ни о каком конкретном соседе по машине.

**Запись — read-modify-write под маской.** Читаем полное слово из
`NFQA_CT`, меняем свои биты, кладём полное обратно. Чужая разметка
переживает наш шаг, даже если мы о ней не знаем.

**Расхождение — буква входа, не показание.** Тег писателя даёт проверку
без памяти: `tag ≠ наш` означает, что по нашим битам писал другой агент.
Сравнение с константой, не с запомненным значением, — иначе zero-state
рушился бы об собственную проверку. Клетка `CtView::Diverged { ours,
theirs }` заселена по образцу `Sensed::Unread` (§7): улика, на которую
прибор вправе среагировать, имеет право быть увиденной, значит идёт во
вход. Приборы без ct-вида проецируют мимо и не платят.

Оттиск лежит в ядре по той же причине, что и фаза: у себя он был бы
таблицей, растущей с числом потоков. В ядре он переживает наш рестарт —
подозрение, поставленное до падения демона, продолжает наблюдаться с
той же точки.

`CTA_LABELS` — запасной носитель, не основной: пятнадцать бит помещаются
в марку с запасом, а labels требуют ненулевого их размера в ядре.
Ширина полей — умолчание, а не закон: маска задаётся снаружи, и три поля
переносятся в labels без изменения остального, если места в марке не
дали.

## Тишина: третьей двери не нужно

Первая редакция вводила «холодный канал» — дамп conntrack по тику для
приборов, срабатывающих в тишине. **Отвергнуто**: §2 говорит, что войти
в шаг можно только буквой входного алфавита, и дамп на тике был бы
третьей дверью.

Развязка проще и лежит в самой задаче: **тишина цели наблюдается на
пакетах клиента.** Цель молчит — клиентское ядро ретрансмитит с
нарастающим таймаутом, и на каждом повторе мы шагаем, имея свежий
`NFQA_CT`. Если же замолчал и клиент, беда никого не беспокоит: жаловаться
некому, а запись заберёт conntrack по своему таймауту.

Тик остаётся тем, чем был (§9.3, тишина обязана доходить), и ядерного
вида не несёт. Приборы, которым нужен ядерный вид, работают по букве
`Packet`.

Push-канал ctnetlink (`NFNLGRP_CONNTRACK_DESTROY`) назван и **не
строится**: второй сокет и вторая машина событий ради случая, которого
пока нет.

## Сертификация

**Предпосылки машины — в `nfqueue/preflight.rs`**, к существующим
`CAP_NET_ADMIN`/`CAP_NET_RAW`/`nfnetlink_queue` добавляются: загружен ли
`nf_conntrack`, включён ли `nf_conntrack_acct`, включён ли
`nf_conntrack_timestamp`, принят ли `NFQA_CFG_F_CONNTRACK`. Первые два
по умолчанию в ядре **выключены**, и без `acct` приборы на счётчиках
вечно видят нули при зелёной сборке. Форма ответа — существующая: причина
плюс рецепт починки.

**Девятый закон — `core/src/certify/remembering.rs`.** Восьмой занят
`replays` (§10, §12.3). Утверждение: состояние, отданное ядру, вернулось
нам следующим шагом того же потока.

```
Broken::StateLost    отдали s — вернулось не s
Broken::Clobbered    наши биты целы, чужие стёрты: RMW сломан
Invalid::NoConntrack у пакета нет NFQA_CT: судить не о чем
Invalid::AnswerNotTaken  терминал сказал, что вердикт не принят
```

Свидетель независим по коду, как требует `certify/mod.rs`: пишем через
дверь очереди (`NFNL_SUBSYS_QUEUE`), читаем через дверь дампа
(`NFNL_SUBSYS_CTNETLINK`) — разные подсистемы, разные сообщения. Разбор
`CTA_*` при этом один и тот же (закон одного чеканщика): независимость
свидетеля здесь в том, ОТКУДА взяты байты, а не в том, кем они разобраны;
второй разбор дал бы независимость ценой двух законов об одной марке.
Дамп остаётся **только свидетелем**: источником буквы на боевом пути он
не становится — иначе появилась бы третья дверь (§2). Закон звучит в `linux/examples/certify.rs` рядом с семью
остальными, на живом ядре.

`Broken::Clobbered` — подстраховка, переведённая из намерения в
проверяемое утверждение: стенд кладёт в чужие биты произвольное значение
и требует, чтобы оно пережило наш шаг.

## Что исчезает

- **`FlowTable` в фасаде** — как хранилище: прибор без состояния живёт
  одним экземпляром на все потоки. Вместе с ним уходят эвикт по простою,
  `MIN_IDLE` и фанаут тиков по ключам. Это касается §12.1 (`Region::Key`):
  боевым потребителем расслоения `FlowTable` больше не будет.
- **Уборка** (§12.5, §12.6): состояния, которого не завели, чистить не
  надо; закон смерти области объявляет conntrack своим таймаутом.

**Остаётся `idents: HashMap<FlowKey, Ident>`** — имя цели из
`ClientHello`. В 32 бита не влезает физически, в 128 бит labels тоже.
Считаем это другим предметом: имя — личность цели для человека, не
состояние автомата (расслоение `Named | Unnamed` уже это говорит).
Вопрос вынесен эксперту канона; если ответ будет «один предмет», спека
дополняется отдельным разделом.

## Швы, по которым копии расходятся молча

Оба названы явно, потому что сборка при их расхождении остаётся зелёной.

**1. Живость потока — один закон, не два.** `FlowTable` держит
юзерспейсные часы простоя (`flow_table.rs`), у conntrack часы свои.
Пока прибор был с состоянием, эвикт нёс и прибор, и запись таблицы.
После `S = ()` приборам хранилище не нужно, но **именам эвикт всё ещё
нужен**, и если он останется юзерспейсными часами рядом с ядерным
таймаутом — это двое часов об одном предмете.

Пока подписки на `NFNLGRP_CONNTRACK_DESTROY` нет (`dump.rs` умеет только
`GET`/`DUMP`), **единственным законом живости объявляется юзерспейсный
простой имён**. Ядерный таймаут вторым законом живости не вводится.
`база − CTA_TIMEOUT` в приборе тишины — не суждение о живости, а
измерение «сколько молчит»; смешивать их запрещено.

Отдельно назван вытекающий отсюда порядок отказа: имя эвиктится по
юзерспейсным часам, а состояние живёт в ядре по своим — значит поток,
переживший эвикт имени, продолжит наблюдаться, а его беда не найдёт
адресата в `fire`. Пока это не закрыто подпиской на `DESTROY`, срок
жизни имени обязан быть **не меньше** ядерного таймаута состояния, и
это условие проверяется, а не подразумевается.

**2. Ключ потока — одна функция, не два понятия.** Ключ таблицы имён и
кортеж conntrack обязаны быть одной и той же личностью потока: `FlowKey`
куётся из того же кортежа, каким индексируется запись ядра
(`CTA_TUPLE_ORIG`). Сегодня он куётся в юзерспейсе из разобранного
провода; после переезда две ковки одного ключа — то же расхождение при
зелёной сборке.

## Порядок работ

0. Сверка ключа: `FlowKey` из `CTA_TUPLE_ORIG` — до всего остального,
   иначе последующие шаги встанут на двух ключах.
1. Свой сокет к очереди: конфигурация, приём, вердикт; разбор `NFQA_CT`
   поверх `conntrack/wire.rs`. Переезд `Terminal`/`Serves` без изменения
   их интерфейса.
2. `CtView` в носитель, `Reads`-проекции существующим приборам.
3. Кодек марки: фаза, оттиск, тег; RMW под маской-параметром; клетка
   `Diverged`.
4. Приборы на ядерные величины: `SynDrop` (`reply.packets == 0`),
   `Retransmit` (рост `orig` при неподвижном `reply`), `Silence`
   (`база − CTA_TIMEOUT` плюс оттиск).
5. `preflight` и девятый закон в `certify.rs`.
6. Снос `FlowTable` из фасада.

Шаги 1–3 ломают сборку межкрейтово и едут вместе; 4–6 отделимы.

## Риски

- **`ENOBUFS` на своей двери.** Крейт гасил его молча; у нас он обязан
  стать величиной, иначе потеря пакетов очереди читается как тишина цели —
  то есть как ложная беда.
- **Разрешение `CTA_TIMEOUT` — 1 секунда.** Окна короче секунды на нём
  не строятся; для `Retransmit` время и не нужно (он на счётчиках).
- **Оттиск в 8 бит** ошибается, если цель ответила ровно кратно 256
  пакетам между двумя нашими наблюдениями. Мы наблюдаем каждый пакет
  потока, так что случай требует нашей же слепоты на 256 пакетов подряд.
- **`nf_conntrack_acct` выключен по умолчанию** — снимается preflight-ом,
  но на чужой машине это самая вероятная причина «приборы молчат».
