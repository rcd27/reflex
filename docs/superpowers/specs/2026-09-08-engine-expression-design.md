# Алфавит есть тип: невыразимое не собирается

> Дизайн-документ. Замеры датированы 08.09.2026 и верны на эту дату.
>
> **Отменяет** `2026-09-07-engine-syntax-design.md` (строитель — не алгебра: ни тождества, ни композиции, а порядок вызовов ничего не значит).

## 1. Закон, из которого выводится остальное

> **ШАГ ЗАМКНУТ ПО ВЛИЯНИЮ: войти можно только буквой, выйти — только словом или показанием.**

Две двери, третьей нет. Построенное за эти дни — следствия одного утверждения, а не список правил: полный входной алфавит (влияет — значит прибывает буквой), время буквой, `Opaque`, адресность слова, показания вбок, пара на выходе, забывание как функтор, уборка по букве, воспроизводимость прогона по `S₀` и ленте букв, граница по ёмкости там, где часов нет.

## 2. Тезис: алфавит есть ТИП, и потому невыразимое не собирается

Полный входной алфавит строился не ради учёта в бою. Он строился, чтобы **тип говорил всё**.

Композиция уже есть сверка алфавитов, и делает её компилятор:

```rust
impl<A: Step, B: Step<From = A::To>> Step for Then<A, B>
```

Отсюда закон синтаксиса, и он сильнее всего, что предлагалось вчера:

> **Цепочка, которой недостаёт подготовки, НЕ СОБИРАЕТСЯ.** Не молчит в бою, не отвечает «не знаю», не ждёт первого пакета, чтобы выяснить, что ей нечем работать. Не компилируется.

**Полнота алфавита и есть то, что делает эту проверку честной.** Будь алфавит частичным — окажись хоть одна возможная буква непредставимой, — шаг проходил бы проверку типов и всё равно встречал в бою то, чего не объявлял. Полнота значит: **если собралось, то всякая буква, которую шаг может встретить, им объявлена.** Вот зачем строился полный алфавит; учёт в бою был следствием.

Дерево это уже подтверждает. Среди реализаций `Step` стоят рядом:

| `type From` | что это за алфавит |
|---|---|
| `DetectorEvent<TcpSegment>` | проволока: сегменты как пришли |
| `DetectorEvent<RecordChunk>` | **уже собранное**: записи TLS |
| `DetectorEvent<UdpDatagram>` | датаграммы |
| `DetectorEvent<Sighting>` | наблюдения края |

Скормить приборy, живущему на `RecordChunk`, сегменты проволоки **сегодня уже нельзя** — `Then` откажет. Проверка есть. Нет стрелки, которой переход совершается.

## 3. Теорема: стрелка, меняющая область, ЕСТЬ расслоение

Области упорядочены по охвату: **пакет ⊂ разговор ⊂ цель**.

> **Перейти из узкой области в широкую нельзя иначе, чем собрав узкое по ключу.** Разговор — это пакеты, сложенные по пятёрке; цель — разговоры, сложенные по адресу. Ключ и есть то, чем область расслаивается.

Отсюда ответ на вопрос, который вчерашняя редакция оставила открытым («как ключ попадает в тип»). **Никак — он там уже есть.** Ключ не параметр цепочки: он **принадлежит области**, потому что смена области без него невозможна. Область обязана его назвать:

```rust
pub trait Region {
    /// Чем область расслаивается. У пакета расслоения нет.
    type Key: Eq + Hash;
}
// Packet::Key = ()   Conversation::Key = Flow   Target::Key = IpAddr
```

Сегодня `trait Region {}` пуст. Это и есть недостающая строка.

Следствие для синтаксиса — то, ради чего всё: **ключевание пропадает из речи потребителя.** Не потому, что спрятано, а потому, что **выведено**. Область объявлена источником, ключ определён областью, расслоение построено движком — один раз, в фреймворке.

```rust
from(TCP)      // область: разговор  — буквы собраны по пятёрке
from(IP)       // область: пакет     — буквы как пришли
```

И тогда пример пишется плоско, без единого упоминания ключа:

```rust
engine(NFQ, from(TCP)
    .filter(has_domain_name)   // вопрос осмыслен: у разговора есть прошлое
    .detect(MtProto)           // прибор живёт на собранном
    .route(FwMark(0xbb)))
```

а неверное построение отвергается на сборке:

```rust
from(IP).detect(MtProto)
// ошибка: ожидалось DetectorEvent<RecordChunk> (область Conversation),
//         найдено   DetectorEvent<IpPacket>    (область Packet)
```

`filter(has_domain_name)` над пакетом отвергается по той же причине и без отдельного правила: у пакета нет прошлого, вопрос в его алфавите не выразим.

## 4. Замер: стрелки нет, и оттого её пишут руками

**`FlowTable` — это расслоение, и оно само так о себе и говорит:** «таблица есть подъём шага на СЕМЬЮ машин, ключёванную потоком». При этом:

* **`Step` она не реализует** (проверено: `impl Step for FlowTable` не встречается нигде). Значит `then` до неё не дотягивается, и в цепочку она не встаёт.
* **Ключ вбит гвоздём**: `In: HasFlow`, `HashMap<Flow, D>`. Расслоение по цели этой же вещью не выражается.

`Over` — подъём **без** расслоения, одна машина на весь поток, и он `Stream`, а не `Step`. Его докблок называет расслоённый подъём как нечто существующее («приписывает паре ключ, и только») — вещи, которой в коде нет.

`Plane` тоже не `Step`; вход у него — рукодельная тройка `(Plan, Packet<'a>, Tick)`, то есть произведение алфавита, собранное на месте.

**Итог: состояние на ключ заведено в тринадцати файлах, двадцать семь карт** (`plane.rs` — девять сразу, `group_by_flow` и `group_by_connection` — по три и дословными дублями друг друга). Причина не в небрежности. **Расслоение невыразимо в алгебре, и каждый обходится как может.**

## 5. Спуск и ноль произведения

**Первая редакция этого раздела была неверна.** Она утверждала: «слово широкой области поглощает слова узких». Дерево говорит обратное, и говорит прямо (`engine/src/step.rs`): приказ по РАЗГОВОРУ старше плана по ЦЕЛИ, то есть узкое перебивает широкое.

Настоящий закон не про охват:

> **Ноль произведения — это ПРЕКРАЩЕНИЕ, а не широта.** Слово, кончающее предмет, поглощает всякое слово, говорящее, КАК его вести. «Больше не ведут» старше «ведут так-то», в какой бы области ни было сказано.

Охват же управляет не силой, а **направлением**, и вот это типом проверяется:

```rust
pub trait Within<Wider: Region>: Region {}   // Packet ⊂ Conversation ⊂ Target

pub trait Descends<Into: Word>: Word
where
    Into::Of: Within<Self::Of>,              // спуск только вниз по охвату
{
    fn descends(self) -> Into;
}
```

Спуск в дереве уже был написан дважды и оба раза безымянно: свободной функцией `acted` (план цели → вердикт пакета) и литералом `Ordered::Sever => Act::Sever` строкой ниже. Ни та, ни другая запись не могла быть проверена на направление — а узкое звено, объявляющее план по цели, которую видит одним своим разговором, было бы законно. Отказ проверен причиной, отдельной сборкой: `the trait bound Conversation: Within<Packet> is not satisfied`.

Промолчать умеет только прекращающее слово, и это несущая деталь: `Ordered` спускается в `Option<Act>`, а не в `Act`. Отдай «обычная жизнь разговора» какой-нибудь `Act::Pass` — и молчание оделось бы в слово и выиграло бы произведение у плана цели.

Транзитивность охвата пишется рукой (`Packet: Within<Target>`): баунд на транзитивном замыкании в системе типов не выражается, а спуск через уровень в бою существует — план по цели решает судьбу пакета, не спрашивая разговора.

## 6. Выражение, а не строитель

У строителя `.to(A)` и `.to(B)` переставимы — это регистрации. У нас порядок несёт смысл, потому что композиция **есть проводка влияния**:

```rust
from(TCP).filter(has_domain_name).detect(MtProto)  // прибор живёт в мире без безымянных
from(TCP).detect(MtProto).filter(has_domain_name)  // фильтруются ВЫВОДЫ; чаще всего не соберётся
```

Движок — **функция от цепочки к потоку показаний**. Слово уходит вниз, области: вердикт применяет бэкенд, он для того и держит пакет. Показания уходят вбок — они и есть значение выражения.

```rust
let notes = engine(NFQ { queue: 0 }, from(TCP).filter(has_domain_name).detect(MtProto).route(FwMark(0xbb)));
notes.wire(otel::span).await
```

`.run()` не нужен: **прогон есть потребление потока**. Терминатор вернул бы строителя через чёрный ход — снова сделал бы конец цепочки особенным местом. Отсюда же бесплатно: **телеметрия не может изменить ни одного вердикта** — показания по §1 не влияют ни на что, а `wire` подключается именно к ним.

## 7. Заготовки собираются нашими же кирпичами

`SilentDrop`, `MtProto`, `RstInjection` — поставка фреймворка. Обязательство: **заготовка не имеет права быть чёрным ящиком.** Тот же алфавит в `From`, та же пара на выходе, тот же адрес у слова, та же область. Тогда сетевик вправе разобрать её на части и собрать своё.

Заготовка, которой понадобилось нарушить закон, — не заготовка, а находка: значит закон неполон, и чинить надо закон.

## 8. Чем это проверяется

* **Отказ на сборке, и по своей причине**: прибор разговора, накормленный пакетами; вопрос к прошлому в пакетной цепочке; ожидание там, где области нельзя ждать; узкое слово, отменяющее широкое. Каждое — `compile_fail`, чья ПРИЧИНА сверяется отдельной сборкой (зелёный `compile_fail` доказывает лишь «не собралось», а читается как «запрещено законом»).
* **Расслоение — одно.** `FlowTable`, `group_by_flow`, `group_by_connection` и карты `Plane` выражаются через одну стрелку; счёт карт падает с двадцати семи. Число — приёмка.
* **Перестановка звеньев меняет машину**, а где бессмысленна — не собирается.
* **Телеметрия не меняет вердиктов**: прогоны с `wire` и без дают побуквенно равные слова.
* **Заготовка разбирается на части**: тест собирает `SilentDrop` из кирпичей и получает то же поведение.

## 9. Открытые вопросы

**1. Форма спуска. СНЯТ ПОСТРОЕНИЕМ (§5).**

Спуск назван стрелкой `Descends`, направление проверено охватом `Within`. Открытым остаётся СВЕДЕНИЕ: кто выбирает между спущенными словами. Сегодня это `unwrap_or_else` у места вызова — верно по существу, но законом не названо, и в другом месте будет написано иначе.

**2. Область объявляет и свою смерть?** Уборка выводится из входного алфавита (спека 07.09): TCP — по букве, UDP/QUIC — по сроку, без часов — по ёмкости. Это свойство ровно той же области, что владеет ключом. Если `Region` называет `Key`, ему же, похоже, принадлежит и закон смерти — иначе один предмет опять окажется в двух местах.

**3. Куда встаёт `CanInject`.** Установлено ранее: в ряду «пакет в руках» ему не место. Решать вслепую — повторить ту же ошибку рядом.
