# Политика уборки выводится из входного алфавита

> Дизайн-документ. Замеры датированы 07.09.2026 и верны на эту дату.
>
> **Первая редакция ставила задачу неверно** и называлась «Ограниченный обход: закон уборки поднимается в фундамент». Она предлагала поднять в фундамент бюджет и курсор — то есть ускорить ОПРОС. Разбор показал, что опрос там, где есть буква, и есть беда: ускорять его значило чинить не то. Прежняя постановка сохранена как §7 — она остаётся верной для одного из трёх случаев.

## 1. Закон

> **Чем чистишь состояние — определяется тем, что ПРИХОДИТ.**

| источник даёт | кто это | чем чистим | почему |
|---|---|---|---|
| **закрытие буквой** (FIN, RST) | **TCP** | **буквой, немедленно** | закрытие уже прибыло; узнавать его обходом значит опрашивать про известное |
| **тик, но не закрытие** | **UDP, QUIC** | **по сроку** | ничего не придёт; отсутствие выразимо только временем |
| **ни закрытия, ни тика** | поток без часов | **по ёмкости** | времени нет вовсе; честная граница одна — число ключей |

Разбиение по протоколам не приблизительное, а точное: **по времени умирают только UDP и QUIC**. У TCP конец объявлен буквой; у UDP конца нет в самом протоколе; у QUIC он есть (`CONNECTION_CLOSE`), но **зашифрован** — с нашего места неотличим от его отсутствия, и потому QUIC стоит в одной строке с UDP не по природе, а по видимости.

Политика не выбирается потребителем. Она **выводится** из того, что даёт источник, и потому у одинаковых источников обязана совпадать.

## 2. Чем эта работа вызвана

### 2.1. Замер: восемь политик, по закону живёт одна

| где | источник | политика сегодня | по закону |
|---|---|---|---|
| `engine_nfq::plane::Plane` | **TCP** | по сроку, обходом с бюджетом | **по букве** |
| `core::expiring_set::ExpiringSet` | ключ + время | по сроку, обход всей карты | по сроку |
| `core::flow_table::FlowTable` | ключ + тик | по сроку, обход всех потоков | по сроку |
| `core::dns::cache` | TTL записи | по сроку + ёмкость | по сроку |
| `runtime::group_by_flow` | ключ + таймер | по сроку (`retain`) + ёмкость | по сроку |
| `runtime::group_by_connection` | то же | **дословный дубль предыдущего** | по сроку |
| `runtime::session_window` | ключ + таймер | по сроку + ёмкость | по сроку |
| `core::stream::group_by` | **часов нет** | по ёмкости | по ёмкости — **верно** |

По закону сегодня живёт одна строка — та, у которой часов не было и выбора тоже.

### 2.2. TCP-конвейер опрашивает про то, что ему уже сказали

`Plane` видит закрытие буквой: шаг сам называет исход (`Cursor::Ended`). Но запись остаётся в таблице и ждёт обхода по таймауту.

Реактивный фреймворк узнаёт о закрытии **дважды** — сперва буквой, потом опросом, — и действует по второму.

### 2.3. Замер удержания (прогоном на `Plane`)

Разговор, замолчавший в нуле; дальше только тики:

```
t =  8,6 с (1 горизонт):  Running
t = 12,9 с (1,5):         Running
t = 17,2 с (2 горизонта): Lost      ← только здесь
t = 25,8 с (3):           Lost
```

Замолчавший держится **живым два горизонта** (17 секунд при горизонте 8,6 с) и лишь потом становится забытым.

Доля забытых в установившемся режиме:

```
разговор  5 с: живых 27, Lost 22 → 44,9 % таблицы
разговор 20 с: живых 14, Lost  6 → 30,0 %
```

Предупреждение, стоящее в самом коде («потолок покрывает вдвое меньше живых»), подтверждено замером: **от трети до половины** таблицы занято памятью, оставленной нарочно.

## 3. Удержание ради честности — отдельная вещь, и она не уборка

Закрытый разговор не стирается сразу **намеренно**: сотри — и на следующий пакет той же четвёрки таблица скажет «не видели» про разговор, по которому мы выносили вердикты. Соврёт не в мелочи, а в главном числе отчёта.

Это не мусор и не недосмотр, а **память ради неложи**, и у неё свой срок.

Отсюда разделение, которого сегодня нет:

* **снятие с живых** — происходит в момент закрытия, по букве;
* **удержание** — сколько ещё помним, что разговор БЫЛ; величина отдельная, названная, к обходу отношения не имеющая.

Смешение этих двух и породило нынешнюю картину: обход по сроку делает работу обоих и оттого не может быть настроен ни под одну.

## 4. Что меняется

**`Plane` (TCP).** Закрытие снимает разговор с живых по букве. Обход остаётся **резервным путём** — для умерших молча (уснуло устройство, выдернули кабель, NAT забыл). Величину этого меньшинства обязан назвать замер (§8.1).

**Удержание** объявляется отдельной величиной со своим сроком, а не следствием горизонта уборки.

**Потребители тика без закрытия** (`FlowTable`, `session_window`, `group_by_flow`, `group_by_connection`, `dns::cache`, `ExpiringSet`) остаются на сроке — иначе им нельзя. Для них и нужен ограниченный обход (§7).

**`group_by`** не трогается: часов нет, политика по ёмкости верна.

## 5. Чем это проверяется

* Разговор, закрытый FIN или RST, **перестаёт быть живым в тот же шаг** — не «в течение горизонта», а на букве.
* Разговор, замолчавший **без** закрытия, снимается по сроку — резервным путём, и это отдельная проверка.
* Пакет по закрытому и снятому разговору не даёт ответа «не видели»: удержание работает и после снятия с живых.
* Доля разговоров, дошедших до резервного пути, — **показание**, а не догадка.

## 6. Что сюда НЕ входит

* **Закон ёмкости** — «место кончилось, выселяй старейшего». Написан не меньше пяти раз, каждый раз полным проходом за минимумом, срабатывает на вставке. Ему нужен не курсор, а быстрый минимум; отдельная работа.
* **Ограничение доставки буквы `Tick`.** Прибор, пропустивший тик, слеп в тишине — в том единственном случае, ради которого тик заведён.
* **Объединение критериев срока.** TTL, простой и «окно закрылось» остаются у своих потребителей.
* **Миграция потребителя.**

## 7. Ограниченный обход — резервный путь, а не главный

Для потребителей, которым закрытие не приходит буквой, прежняя постановка остаётся верной: бюджет, курсор и остаток-показание. С двумя поправками, найденными при разборе.

**Курсор с `range` требует упорядоченного хранилища.** Шесть потребителей из семи держат `HashMap`, где порядок обхода между мутациями не сохраняется и «продолжить с последнего ключа» невыразимо. Приложимые формы: снимок ключей раз в круг (не трогает ни хранилище, ни горячий путь) либо переезд на упорядоченную карту (платит на каждом пакете). Выбор — за замером, когда до этого дойдёт дело.

**Идиома продвижения курсора в `Plane` требует лишнего.** `FlowKey(last.saturating_add(1))` работает только для целочисленного новотипа и на верхней границе типа перестаёт двигаться вовсе. Полуинтервал по исключённой границе даёт то же намерение без обоих свойств. Установлено чтением; попадания в бою не наблюдалось.

**Остаток обязан быть показанием.** `Swept { looked, left }` — завал виден величиной заранее, а не через отставание таймера. Опыт Zeek на том же месте: отставание 1330 секунд на 2 млн записей, вывод «истекать помалу, но часто».

## 8. Открытые вопросы

**1. Сколько разговоров умирает молча. СНЯТ доменным знанием.**

По времени умирают **только UDP и QUIC**; TCP объявляет конец буквой. Значит в TCP-конвейере обход по сроку — редкое исключение: уснувшее устройство, выдернутый кабель, забывший NAT. Резервный путь остаётся, но перестаёт быть предметом настройки: ему довольно длинного срока и малого бюджета, а курсорной механики не нужно вовсе.

Величина исключения (доля TCP-разговоров, умерших без буквы) остаётся полезной как **показание**, но не как условие постройки: она говорит о качестве сети, а не о форме кода.

**2. Каков срок удержания. НЕ МИНА: меняет константу, не подпись.**

Сегодня удержание получилось следствием двух горизонтов уборки и никем не выбиралось. Оно обязано стать названной величиной с доводом: сколько времени пакет по закрытому разговору ещё возможен.

**3. Кому принадлежит вывод политики. НЕ МИНА, но решить до плана.**

Закон говорит «политика выводится из источника». Выражается это типом (источник объявляет, даёт ли он закрытие буквой) либо соглашением. Типом — сильнее и в духе адресного слова; соглашением — дешевле.
