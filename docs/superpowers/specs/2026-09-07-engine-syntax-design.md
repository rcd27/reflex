# Синтаксис движка: `engine(NFQ) { … }`

> **ОТМЕНЕНА** редакцией `2026-09-08-engine-expression-design.md`. Здесь предложен СТРОИТЕЛЬ; у строителя нет ни тождества, ни композиции, а порядок вызовов ничего не значит — тогда как у нас порядок звеньев несёт смысл. Разбор — в §3 новой редакции. Замеры и разбор нынешнего дерева ниже остаются верными.
>
> Дизайн-документ. Замеры датированы 07.09.2026 и верны на эту дату.

## 1. Чем эта работа вызвана

Спека полного алфавита (06.09.2026, §7) отложила синтаксис словами: «Следующий срез. Без §3–§5 это была бы обёртка над той же рванинои». §3 — полный входной алфавит, §5 — пара на выходе. Оба построены и слиты. Препятствие снято.

### 1.1. Что сегодня пишет тот, кто собирает движок

Сборка живёт в `engine-nfq/src/bin/plane-queue.rs` — **495 строк**, из которых домену принадлежит меньшая часть: разбор аргументов, засев знания, поднятие очереди, потоки, часы, счётчики, печать. Конвейер как таковой в этом файле не выражен вовсе — он собран из вызовов, а не объявлен.

Следствие названо прежней спекой: **рванина на шве**. Всякий, кто соберёт второй движок, напишет ту же проводку заново и по-своему.

### 1.2. Что уже готово и чего ждать больше не нужно

| закон | где стоит | что даёт синтаксису |
|---|---|---|
| полный входной алфавит | `core::detector::DetectorEvent` | драйверу нечего добавить: `Packet`, `Opaque`, `Tick` |
| время буквой | `core::grid`, `runtime::timed::on_grid` | `.every(…)` выражается сеткой, а не сном |
| слово адресно | `core::word` | `.to(Область, …)` проверяется компилятором |
| цвет области | `core::word::CanDefer`, страж | ожидание на пакетной цепочке невыразимо |
| пара на выходе | `core::step::Step` | показания уходят вбок, `.notes_to(…)` |
| политика уборки из алфавита | спека 2026-09-07 | `from(TCP)` и `from(UDP)` требуют разного |
| способности бэкенда | `core::capability`, `core::held` | движок не даёт сказать то, чего бэкенд не умеет |

## 2. Что синтаксис обязан выразить

```rust
use reflex::prelude::*;

fn main() -> Run {
    engine(NFQ { queue: 0 })
        .from(TCP)
        .every(100.ms)

        .to(Target, |talk| {
            talk.silent(after: 1500.ms)
                .or(talk.no_bytes())
                .mark(BYPASS)
        })

        .to(Conversation, |talk| {
            talk.reset().sever()
        })

        .notes_to(Journal::stdout())
        .run()
}
```

Разбор построчно — каждая строка есть следствие уже стоящего закона, а не новая выдумка.

**`engine(NFQ { queue: 0 })`** — бэкенд назван значением. Отсюда известны его способности (`CanHold`, `CanRefuse`, `CanMark`, `CanRewrite`, `CanSever`), и словарь цепочек сужается ими: `.sever()` законен на NFQUEUE и **не собирается** на бэкенде, который рвать не умеет.

**`.from(TCP)`** — источник называет, что приходит. Отсюда выводится политика снятия состояния: у TCP закрытие приходит буквой, значит карточка снимается по `FIN`/`RST`. У датаграмм закрытия нет, и тогда:

```rust
.from(UDP)                       // НЕ СОБИРАЕТСЯ: политика уборки не выведена
.from(UDP).forget_after(30.s)    // законно: срок назван явно
```

**`.every(100.ms)`** — шаг сетки. Тик становится буквой входа; ни один прибор часов не дёргает.

**`.to(Область, …)`** — цепочка, говорящая слово этой области. Областей столько, сколько адресатов: пакет, разговор, цель, объявленная своя. Слить цепочки разных областей нельзя — это уже кусается в дереве (`E0271` на паре слов с разными `Of`).

**Ожидание разрешено областью, а не вкусом.** Цепочка к цели терпит `.ask(dns)`; цепочка, отвечающая пакету, — нет, и это невыразимо, а не нежелательно.

**`.notes_to(…)`** стоит отдельной строкой намеренно: показания не часть конвейера. Внутри цепочки их не читает никто; наружу они выходят подъёмом.

**Пакетный вердикт не пишется.** NFQUEUE требует ответа на каждый пакет; движок отвечает `Act::Pass`, пока цепочка не сказала иного. Сетевик пишет только отличие от «пропустить».

## 3. Словарь бэкенда: удерживаемая область

Замер 06.09.2026, вошедший в прежнюю спеку: пять способностей NFQUEUE — `CanHold`, `CanRefuse`, `CanRewrite`, `CanSever`, `CanMark` — суть **пять слов об одном**: «пакет в руках». А `CanInject` стоит в том же ряду **зря**: AF_PACKET заявляет его, не имея вердикта вовсе.

Отсюда форма: бэкенд объявляет не список глаголов, а **область, которую даёт держать**, и слова к ней.

```rust
/// ЧТО БЭКЕНД ДАЁТ ДЕРЖАТЬ.
///
/// Держать пакет и уметь его пометить — не два свойства, а одно: пока пакет в руках, к нему
/// применимо всё, что область допускает. Бэкенд, который пакета не держит, не «умеет меньше
/// глаголов» — у него другой предмет.
pub trait Backend {
    /// Область, которую этот бэкенд даёт удерживать.
    type Holds: Region;
    /// Слово, которым отвечают удержанному.
    type Verdict: Word<Of = Self::Holds>;
}
```

`CanInject` при этом уезжает из ряда: вбрасывание не есть ответ удержанному — это отдельная способность, и её место определяется отдельно.

## 4. Форма: строитель, а не макрос

Синтаксис собирается **строителем на типах**, не декларативным макросом.

Довод один и он решающий: вся сила сказанного выше — в том, что **компилятор отказывает**. `.sever()` на бэкенде без способности, `.ask()` на пакетной цепочке, склейка слов разных областей, `from(UDP)` без срока — всё это обязано быть ошибкой сборки с внятным местом. Макрос, разворачивающийся в код, переносит ошибку внутрь развёртки, и сообщение указывает не туда, где написана неправда.

Цена названа: строитель многословнее макроса на несколько символов. Взамен всякая ошибка указывает на строку, которую написал человек.

## 5. Чем это проверяется

* **Отказ там, где обещан отказ.** Док-тесты `compile_fail` на каждое из четырёх мест: способность, цвет, область, политика уборки. Каждый обязан отказывать **по своей причине** — причина сверяется отдельной сборкой, а не зелёным статусом теста.
* **Сборка живого движка короче нынешней.** Мерилом служит `plane-queue`: сколько строк занимает объявление конвейера против нынешней проводки.
* **Поведение не изменилось.** Движок, собранный синтаксисом, на той же записи провода даёт те же вердикты, что нынешняя сборка.

## 6. Что сюда НЕ входит

* **Буквы `Taught` и `Commanded`** — внешняя петля и приказ снаружи. Их форма зависит от вопросов, оставленных открытыми сознательно.
* **Второй этаж** — цепочка, чьим входом служит поток показаний предыдущей.
* **Место `CanInject`.** Установлено, что в ряду «пакет в руках» ему не место; куда он встаёт — отдельный вопрос, и решать его вслепую значит повторить ту же ошибку рядом.
* **Миграция потребителя.**

## 7. Открытые вопросы

**1. Чем именно `from(TCP)` отличается от `from(UDP)` в типах. МИНА: ответ задаёт подпись, которой пользуются все цепочки.**

Варианты: источник — тип с ассоциированным «приходит ли закрытие»; либо два разных строителя. Первое единообразнее, второе проще читается в ошибке компилятора. Решается замером сообщений об ошибке, а не вкусом: предмет здесь — что увидит человек, написавший неправду.

**2. Как цепочка называет прибор. НЕ МИНА.**

В наброске — `talk.silent(after: 1500.ms)`, то есть приборы висят методами на «разговоре». Альтернатива — значения (`SilenceInstrument::after(…)`), как сегодня. Первое короче, второе не требует держать список методов в одном трейте.

**3. Кто собирает `Act` для пакета, за который никто не высказался. НЕ МИНА: тело одной функции.**

Движок отвечает `Pass`. Вопрос лишь в том, где это записано законом — в бэкенде (у него потолок и очередь) или в движке.
