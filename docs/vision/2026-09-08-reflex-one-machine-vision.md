# Reflex: одна машина

Формальное описание объекта, на котором построен reflex, и законов, которым он подчинён.
Утверждения либо доказаны здесь, либо сведены к результату из литературы; ссылки в квадратных
скобках раскрыты в конце. Под каждым разделом — строка реализации.

Документ описывает машину, а не историю её постройки: обоснования отдельных решений живут в
докблоках кода, хронология — в git.

## 0. Обозначения

`Set` — категория множеств. `X × Y` — произведение, `Y^X` — множество функций `X → Y`,
`X^ω` — множество бесконечных последовательностей над `X`, `∐` — копроизведение, `1 = {∗}`.

Всюду ниже `In` — входной алфавит, `Out` — выходной, `S` — носитель состояния.

## 1. Объект: машина Мили как коалгебра

**Опр. 1.1.** Пусть `In`, `Out` — множества. *Машиной* называется пара `(S, β)`, где

```
β : S → (S × Out)^In
```

Это коалгебра эндофунктора `F(S) = (S × Out)^In` на `Set` [Mealy 1955; Rutten 2000, §2].
Каррирование `S × In → S × Out` в `S → (S × Out)^In` есть биекция; далее используются обе формы.

*Реализация:* `core/src/mealy.rs` (`trait Mealy`, `fn step`). Показания (`type Log`) вынесены
в §3.4 и структуры коалгебры не меняют.

**Опр. 1.2.** Функция `g : In^ω → Out^ω` *каузальна*, если `n`-й член `g(σ)` зависит только от
`σ₀…σₙ`.

**Теорема 1.3 (финальность).** `F` имеет финальную коалгебру; её носитель — множество `Γ`
каузальных функций `In^ω → Out^ω` [Rutten 2006].

*Доказательство (схема).* Для `(S, β)` определим `⟦·⟧ : S → Γ`, где `⟦s⟧(σ)` есть поток выходов
прогона `β` из `s` по `σ`. Каузальность выполнена по построению: `n`-й выход берётся с `n`-го
шага. `⟦·⟧` — морфизм коалгебр; он единственный, ибо два морфизма в `Γ` совпадают на всех
конечных префиксах по индукции, а элементы `Γ` различаются только значениями на префиксах. ∎

**Следствие 1.4.** Поведение машины есть элемент `Γ`. Два состояния наблюдательно неразличимы
тогда и только тогда, когда равны их образы в `Γ`; это финальная семантика бисимуляции
[Rutten 2000, §3].

**Опр. 1.5.** Состояние передаётся *значением*: `β` действует на `S`, а не на ссылку в `S`.

**Утв. 1.6.** При Опр. 1.5 прогон есть функция от `(s₀, σ)` и только от них.

*Доказательство.* `β` — функция; композиция функций по конечному префиксу `σ` — функция. Иного
аргумента у прогона нет по Опр. 1.1. ∎

Утв. 1.6 — предпосылка §10: воспроизводимость доказывается здесь, предъявляется там.

## 2. Замкнутость по влиянию: полнота входного алфавита

**Опр. 2.1.** Алфавит `In` *полон* для машины `m`, если всякая буква, которую `m` может встретить,
лежит в `In`.

**Утв. 2.2.** При нарушении полноты `(S, β)` не есть коалгебра `F` на `S`.

*Доказательство.* Пусть шаг зависит от `h ∈ H`, не входящего в `In`. Тогда шаг есть функция
`S × In × H → S × Out`, то есть коалгебра `F` на носителе `S × H`, а не на `S`. Проекция
`S × H → S` не есть морфизм коалгебр: она не сохраняет `β`. Следовательно, по Следствию 1.4
наблюдательная эквивалентность, вычисленная на `S`, не есть эквивалентность поведения. ∎

Скрытым входом является всякий источник недетерминизма, не объявленный буквой: часы, глобальное
состояние, захваченное окружение замыкания.

**Опр. 2.3.** Входной алфавит reflex:

```
In  =  Packet ⊔ Tick ⊔ Opaque ⊔ Torn
```

`Packet` — наблюдение; `Tick` — узел временнóй сетки (§8); `Opaque` — кадр получен и не разобран;
`Torn` — наблюдения были и не получены. `Opaque` и `Torn` различны по предмету: первое есть
незнание о содержимом полученного, второе — знание о неполучении.

*Реализация:* `core/src/detector.rs` (`enum DetectorEvent`).

## 3. Композиция

**Опр. 3.1.** Для `β : S → (S × B)^A` и `γ : T → (T × C)^B`:

```
(γ ∘ β)(s, t)(a)  =  ((s′, t′), c),   где  (s′, b) = β(s)(a),  (t′, c) = γ(t)(b)
```

**Опр. 3.2.** `id_A = (1, ι)`, где `ι(∗)(a) = (∗, a)`.

**Утв. 3.3.** Машины суть морфизмы категории с объектами-алфавитами — с точностью до канонических
изоморфизмов носителя.

*Доказательство.* Ассоциативность: обе расстановки скобок дают один выход и одни состояния,
различаясь лишь скобками носителя, `(S × T) × U` против `S × (T × U)`; канонический изоморфизм
произведения переводит одно в другое и коммутирует с шагом. Единица: `1 × S ≅ S` аналогично.
Строгого равенства носителей нет, и утверждать его нельзя: композиция ассоциативна как операция
над классами изоморфных носителей. ∎

Оговорка существенна и в коде: носитель композиции — кортеж, а вложенные кортежи разной
скобочности суть разные типы. Совпадают они поведением, не представлением.

*Реализация:* `core/src/mealy.rs` (`Compose`, `Id`, `MealyExt::then`).

**3.4. Показания.** Показания композиции — произведение показаний звеньев,
`Log(γ ∘ β) = Log(β) × Log(γ)`. Произведение, а не общий словарь: автор показания назван позицией
в кортеже. Отсюда звенья не обязаны говорить на одном языке, и сосед не читает сказанное не ему
(§4.1).

## 4. Область: расслоение по ключу

**Опр. 4.1.** База `B` — линейный порядок областей `Packet ⊑ Conversation ⊑ Target`. Каждой
области `R` сопоставлен ключ `K(R)`:

```
K(Packet) = 1        K(Conversation) = Flow        K(Target) = Named ⊔ Unnamed
```

Слой над `R` индексирован `K(R)`. Проекция `p : E → B` есть расслоение Гротендика
[Jacobs 1999, гл. 1].

**Утв. 4.2.** Смена области вверх есть копредел по слою:

```
Conversation ≅ ∐_{k ∈ Flow} Packet          Target ≅ ∐_{k ∈ Addr} Conversation
```

*Доказательство.* Смена области вверх — левое расширение Кана вдоль проекции ключа
[Mac Lane 1998, гл. X]. Для дискретного слоя левый Кан вычисляется поточечно копределом по слою, а
копредел по дискретному индексу есть копроизведение. ∎

**Следствие 4.3.** Ключ не есть параметр цепочки: он принадлежит области, ибо без него смена
области не определена.

**Утв. 4.4 (потолок носителя).** Носитель состояния ограничен сверху той областью, ключ которой он
различает. Ядро различает `Flow` и `Unnamed(Addr)` и не различает `Named`; следовательно носителя
в ядре для области с ключом `Named` не существует.

*Реализация:* `core/src/word.rs` (`Base::Fibre`), `engine/src/row.rs` (`TargetKey`).

### 4.1. Автор обязателен

**Опр. 4.5.** Ресурс `r`, участвующий в шаге, *несёт автора*, если он либо занимает позицию в
произведении носителей (§3), либо индексирован ключом области (§4).

**Утв. 4.6.** Если две машины `(S, β)` и `(T, γ)` читают и пишут общий ресурс `r ∈ R`, не несущий
автора, их совместный шаг не есть произведение коалгебр.

*Доказательство.* Совместный шаг определён на `S × T × R` и в общем случае не факторизуется как
`β × γ`: значение, записанное `β` в `r`, меняет выход `γ`. Значит проекции `S × T × R → S` и
`S × T × R → T` не суть морфизмы коалгебр, и по Следствию 1.4 поведение сомножителя не определено
его собственным носителем. Утверждения, доказанные о `(S, β)` отдельно, на композицию не
переносятся. ∎

**Следствие 4.7.** Общий безымянный ресурс отменяет одновременно обещание §3 (автор назван
позицией) и обещание §4 (слово адресовано области), не нарушая типизации.

Две реализации авторства:

* по ключу — адрес едет в самой букве: `TapeLetter::Event { to, … }`, `To = One ⊔ Each ⊔ Nobody`
  (`core/src/tape.rs`, `core/src/interleave.rs`);
* по позиции — писатель объявлен типом: `IntoProbe::Home`, `MarkHome = MarkSilent ⊔ MarkWriter`
  (`reflex/src/lib.rs`); второй писатель одного ресурса не собирается.

## 5. Слово: полурешётка с поглощающим нулём

**Опр. 5.1.** `(W, ⊓)` — коммутативная идемпотентная полугруппа (полурешётка сведения) с
поглощающим элементом `stop`:

```
∀ w ∈ W :   stop ⊓ w  =  stop
```

Поглощение выражает: слово, прекращающее предмет, старше всякого слова о том, как предмет вести.

**Опр. 5.2.** Охват — ось, ортогональная силе. `Within` — частичный порядок на областях;
`Descends : W@R → W@R′` определён лишь при `R′ ⊑ R`.

**Утв. 5.3.** Спуск в обратную сторону не определён.

*Доказательство.* По Опр. 4.1 слово области `R` есть слово о классе элементов, склеенных ключом
`K(R)`. Отображение вниз выбирает представителя класса; отображение вверх строило бы класс по
одному представителю, что не функция. ∎

Ограничение несёт баунд `Into::Of: Within<Self::Of>` и проверяет компилятор. Транзитивность
`Packet ⊑ Target` записана явно: транзитивного замыкания баунда система типов не выражает.

**Утв. 5.4.** Молчание принадлежит только прекращающему слову; спуск имеет тип `Option<Act>`.

*Доказательство.* Пусть молчание одето в элемент `pass ∈ W`. Тогда `pass` участвует в сведении
наравне с прочими и конкурирует с планом области, тогда как отсутствие слова в сведении не
участвует вовсе. Отсутствие элемента и нейтральный элемент различаются именно здесь. ∎

*Реализация:* `core/src/word.rs` (`trait Within`, `trait Descends`).

## 6. Область определённости: restriction-категория

**Опр. 6.1.** Категория с *ограничением* сопоставляет каждому морфизму `f : A → B` идемпотент
`f̄ : A → A` — его область определённости, вычислимую без выполнения `f`. Несущая аксиома:

```
f ∘ f̄  =  f
```

Полный список аксиом и теория частичных отображений: [Cockett & Lack 2002].

**Следствие 6.2.** Проверка готовности состояния не меняет и потому законна в любой момент. Отсюда
выходной алфавит шага `Advanced ⊔ NotReady ⊔ Failed`, где `NotReady` отличен от `Failed`.

**Следствие 6.3.** Необязательное звено выражается `f ⊔ id` — той же алгеброй, что §3, а не особым
случаем у вызывающего.

**Область применимости раздела.** Структура ограничения построена в крейте `reflex-os`, где
`Level<bool>` и есть идемпотент `f̄`, а законы проверены ИСЧЕРПЫВАЮЩИМ перебором конечного мира при
наблюдательном равенстве: идемпотентность, коммутативность и ассоциативность встречи, единица
встречи, сохранение тождества и композиции, и сама аксиома Опр. 6.1
(`os/tests/restriction_laws.rs`).

Машины §1–§5 идемпотента `f̄` НЕ несут: в `core`, `engine`, `instrument` и фасаде его нет, и
`reflex-os` не входит в граф зависимостей ни одного из них. Раздел описывает структуру, соседнюю
машине, а не её собственную. Распространять Опр. 6.1 на морфизм §1 без построения нельзя.

## 7. Незнание: обитаемая клетка выходного алфавита

**Опр. 7.1.** Выходной алфавит *тотален*, если содержит клетку «не наблюдал», отличную от клетки
«наблюдал пустоту».

```
Told    = Nothing ⊔ Blind
Served  = Answered ⊔ Idle ⊔ Blind ⊔ Torn
Sight   = Full ⊔ Partial
Verdict = Held ⊔ Broken ⊔ Invalid
```

`Idle`, `Blind`, `Torn` попарно различны: работы не было; ждать не на чем; работа была и не дошла.

**Утв. 7.2.** Алфавит без клетки «не наблюдал» отображает дефект наблюдателя в утверждение о мире.

*Доказательство.* Пусть выход `o` означает «события не было». Наблюдатель, не смотревший, обязан
выдать элемент `Out`; единственный доступный — `o`. Тогда `o` истинно и при отсутствии события, и
при отсутствии наблюдения, то есть их не различает. ∎

### 7.1. Незнание как действие на состояние

Опр. 7.1 населяет выход. Требуется связь: буква входа, прячущая наблюдение, обязана изменить
состояние.

**Опр. 7.3.** `H ⊆ In` — множество *прячущих* букв: тех, после которых отсутствие наблюдения
перестаёт быть свидетельством. Для reflex `H = { Torn } ∪ { Opaque(Truncated) }`; прочие `Opaque`
в `H` не входят, ибо чужой протокол не мог нести ответ этого разговора.

**Опр. 7.4.** Машина `(S, β)` *слепнет корректно*, если для всякого `h ∈ H` и всякого `s ∈ S`ни
один выход, достижимый из `β(s)(h)`, не утверждает свойство мира, свидетелем которого было бы
наблюдение, пропавшее вместе с `h`.

**Утв. 7.5.** Тождественное поведение на `H` корректно тогда и только тогда, когда выполнено хотя
бы одно из условий:

* (а) выход утверждает свойство наблюдателя, а не мира;
* (б) вывод не использует отсутствие — доказано типом либо разбором осей;
* (в) отсутствие имеет независимого свидетеля.

*Доказательство.* Достаточность: при (а) утверждение не о мире и Опр. 7.4 неприменимо; при (б)
пропавшее наблюдение не входит в посылки вывода; при (в) свидетельство сохраняется помимо
пропавшего наблюдения. Необходимость: если не выполнено ни одно, вывод использует отсутствие как
свидетельство свойства мира, а отсутствие вызвано `h`, что противоречит Опр. 7.4. ∎

Критерий `H` определён один раз (`DetectorEvent::hides_observation`) и вызывается по имени.
Обязанность Опр. 7.4 исполняется каждой машиной в её шаге; система типов её не проверяет (§12.8).

**Утв. 7.6 (предел).** Момент буквы `Torn` есть момент обнаружения потери, а не момент потери.

*Доказательство.* Источник буквы — уведомление ядра `ENOBUFS`, не несущее ни числа потерянных
сообщений, ни времени. Иного источника нет. ∎

Следствие: окно между потерей и её объявлением принято машинами за полное, и всякое утверждение
«окно свободно от дыры» означает «свободно от объявленной дыры».

*Реализация:* `core/src/detector.rs`.

## 8. Время: буква входа

**Опр. 8.1.** `Tick ∈ In`. Часов у морфизма нет; периодичность выражается сеткой узлов, а не сном.

**Утв. 8.2.** При Опр. 8.1 у машины одна точка входа.

*Доказательство.* Следствие Утв. 2.2: часы, не объявленные буквой, суть скрытый вход, и носителем
коалгебры оказывается `S × H`. ∎

**Опр. 8.3.** Шов сводит поток пакетов и узлы сетки в один монотонный поток букв, выдавая сперва
все перешагнутые узлы и лишь затем пакет.

**Утв. 8.4.** Порядок Опр. 8.3 необходим.

*Доказательство.* Пусть пакет с моментом `t` выдан раньше узла `u < t`. Машина, ведущая счёт по
окнам сетки, отнесёт его к окну, закрытому в `u`, то есть к чужому окну. ∎

*Реализация:* `core/src/interleave.rs`, `core/src/grid.rs`.

## 9. Мир: функтор из морфизма в драйвер

Морфизм не касается мира; его вносит функтор. Функторы различаются линейностью ресурса.

| носитель | линейность | обязательство |
|---|---|---|
| `Source` | копия | наблюдение без ответа |
| `Sink` | вброс | добавить в сеть |
| `Serves` | владение | обязан ответить удержанному |

**Опр. 9.1 (шов).** `serve(&mut self, until, decide)`. Закон: не возвращаться раньше `until`,
кроме как с работой.

**Утв. 9.2.** Срок обязан стоять в подписи шва.

*Доказательство.* Ждать умеет владелец дескриптора; знать, сколько ждать, — владелец часов (§8).
Это разные стороны шва. Подпись без срока их не связывает, ожидание заводится вне шва, буквы
`Tick` в течение ожидания не порождаются — и машины, чей предмет виден только в тишине, не шагают
именно в тишине. ∎

*Реализация:* `core/src/backend.rs`, `core/src/serves.rs`.

### 9.1. Способности

**Опр. 9.3.** Носитель объявляет область, которую даёт держать, и слово к ней:
`trait Backend { type Holds: Region; type Verdict: Word<Of = Self::Holds>; }`. Способности `Can*` —
предикаты на образе функтора.

**Правило 9.4.** Цепочка со словом `w` собирается над носителем `B` тогда и только тогда, когда
область `w` покрыта `B::Holds` и `w` лежит в образе способностей `B`. Требование способности стоит
в точке создания акта, а не на цепочке.

**Правило 9.5.** Способность, метод которой возвращает `None` постоянно для данного носителя, не
заявляется. `None`, зависящий от входа, законен.

**Правило 9.6 (сужение обещания).** Носитель заявляет ровно ту широту, какую может исполнить.
Пример: `EdgeView::down_bytes` обещает байты кадров (L3+L4+нагрузка), а не байты нагрузки, ибо
conntrack нагрузки не наблюдает.

*Реализация:* `core/src/capability.rs`, `core/src/edge.rs`.

### 9.2. Подъём

`Lift` поднимает морфизм в поток; функтор идёт только вверх. Стену образует конкурентность, а не
время: у шага второй нити нет. Поток есть один из драйверов, не носитель категории.

### 9.3. Тишина

Машина шагает на каждой букве `Packet ⊔ Tick`; ответ отдаётся там, где есть кому отвечать.

**Утв. 9.7.** Отдельная клетка ответа не нужна.

*Доказательство.* Отвечает терминал, достижимый только на пакетной букве; тиковая до него не
доходит. Значит различие «ответили / промолчали» вычисляется по букве и самостоятельного состояния
не несёт. ∎

## 10. Предъявимость: финальность и её свидетель

**Опр. 10.1.** Лента — конечная последовательность букв `[b₁ … bₙ]` с начальным состоянием `S₀`.
Прогон даёт последовательность четвёрок `(S_до, in, S_после, out)`.

**Утв. 10.2.** Два прогона одной ленты из одного `S₀` согласны тогда и только тогда, когда машина
детерминирована по объявленному алфавиту.

*Доказательство.* Достаточность — Утв. 1.6. Необходимость: расхождение прогонов означает
зависимость шага от аргумента вне `(S, In)`, то есть скрытый вход, что противоречит §2. ∎

**Следствие 10.3.** Происхождение вывода не требуется нести на горячем пути: оно восстанавливается
прогоном. Образ машины в финальной коалгебре (Теорема 1.3) определён её поведением на лентах.

**Опр. 10.4.** Буква ленты несёт адрес `To = One ⊔ Each ⊔ Nobody` (§4.1). Три значения, а не «ключ
либо его нет»: у узла сетки ключа нет по существу, у непонятого — потому что взять неоткуда.

**Опр. 10.5.** Исход сверки: `Replayed = Agreed ⊔ Disagreed ⊔ Silent`.

**Утв. 10.6.** Без клетки `Silent` закон о воспроизводимости тривиально выполняется на пустом окне.

*Доказательство.* Окно без живых машин даёт пустые последовательности выходов в обоих прогонах;
равенство пустых выполнено. Значит вердикт «воспроизведено» не отличает воспроизводимость от
отсутствия предмета. ∎

### 10.1. Свидетель обязан доказать зрячесть

**Правило 10.7.** Зелёный результат проверки не считается, пока не показана способность той же
проверки дать красный.

**Правило 10.8.** Замер не считается, пока ненулевое значение не показано *тем же* оракулом,
которым ведётся замер.

Правило 10.8 строже 10.7 на выбор инструмента: два оракула одной величины могут расходиться («до
очереди не дошло» против «мы не забрали»), и зрячесть одного не доказывает зрячести другого.

**Следствие 10.9.** Проверка, слепая к своему классу по построению, есть отсутствие проверки.
Инструмент обязан подтверждать принадлежность классу признаком, а не именем.

*Реализация:* `core/src/certify/`, `scripts/portable.sh`, `scripts/canon.sh`.

## 11. Наружу: один контракт

```
engine(носитель)
    .from(транспорт)
    .extract(…)
    .detect(прибор)
    .on(…) | .act(…)
    .run()
```

**Утв. 11.1.** Это выражение, а не строитель.

*Доказательство.* У строителя регистрации переставимы. Здесь порядок несёт смысл, ибо композиция
есть проводка влияния (§3), и перестановка не собирается: прибор чужого алфавита не встаёт в пайп,
второй писатель марки не встаёт за первым (§4.1), свёртка без реакции не собирается. Проверяет
тип. ∎

**Утв. 11.2.** Носитель — голова выражения; всё ниже первой строки от него не зависит.

Три оси полиморфизма: транспорт (`.from`), прибор (`.detect`), терминал (`.on` наблюдает, `.act`
действует). Поперёк стоит область: `.on` слышит слова разговоров, пара
`.about(свёртка).on_target(реакция)` — слово о цели (§4). Пара держится типом.

**Утв. 11.3.** Конец цепочки — место, где называется линейность ресурса (§9) и стоит гейт
способности (§9.1). `Report` есть значение несостоявшегося запуска, а не строитель.

*Предел.* Реакция приходит замыканием, а не значением; §10 сверяет слова машины, но не то, что
потребитель с ними сделал.

*Реализация:* `reflex/src/lib.rs`.

## 12. Открытое

Пункты в порядке веса; номера — в порядке заведения.

**12.1. Связь ключа с носителем семьи.** Ключ области (`Base::Fibre`) ВЗЯТ копределом:
`Colimit` индексирует сказанное слоями `Wide::Fibre` и `Narrow::Fibre` и стоит на боевой двери
фасада (§4, `Target ≅ ∐ Conversation`). Не взят он таблицей потоков: `FlowTable` обобщена по
параметру `K` и получает ключ от ВЫЗЫВАЮЩЕГО, а не из области. Открыт, стало быть, не сам ключ, а
его связь с этим носителем.

Второе, отдельное: состояние по ключу `Flow` лежит в двух носителях — марке ядра и таблице
фасада; по Утв. 4.4 оба допустимы, и выбор между ними не выведен.

**12.8. Носитель слепоты в типах.** §9.1 проверяет способности типом: несобирающаяся цепочка.
Опр. 7.4 проверяется мутацией. Вопрос: выразимо ли «машина зависит от полноты входа» типом так,
чтобы неисполнение не собиралось, — или зависимость от полноты есть свойство смысла машины, типом
невыразимое. Второе не хуже первого, но должно быть установлено, а не подразумеваться.

**12.2. Сведение спущенных слов.** `Descends` построен, направление доказано (Утв. 5.3). Кто
выбирает между спущенными словами — не определено.

**12.5. Наряд на работу из алфавита.** Состояние, которого не завели, не требует уборки;
следовательно часть задачи об уборке выводится из входного алфавита.

**12.6. Закон смерти области.** Уборка выводится из входного алфавита: TCP — по букве, UDP — по
сроку, без часов — по ёмкости. Свойство той же области, что владеет ключом (§4).

**12.7. Четвёртая ось паспорта.** `Shape = Quantity ⊔ State ⊔ Event ⊔ Verdict ⊔ Series` говорит,
какие операторы законны над выходом. Свойство алфавита или отдельная ось — не установлено. Новая
ось вводится, лишь предъявив наблюдение, которое без неё не объясняется.

### Закрытое

**12.3. Воспроизводимость.** Утв. 10.2, Опр. 10.5. Остаётся лента через процесс: `Instant` между
процессами не переносится, и запись, пережившая процесс, требует другой буквы времени (§8).

**12.4. Замыкание движка.** Функтор носителя доведён до фасада; дубль таблицы вердикта устранён по
построению; носитель есть параметр (§11).

### Чего категория не моделирует

Названо, чтобы не предлагалось заново.

* **Конкурентность внутри шага.** У шага одна нить; параллелизм живёт в драйвере (§9.2).
* **Порядок байтов и кодогенерация.** Проявляются в исполнении, а не в типах; проверкой типов не
  ловятся ни на какой цели (Следствие 10.9).
* **Действия потребителя над словом.** §10 сверяет слова машины (предел §11).

## Резюме

Объект — коалгебра `β : S → (S × Out)^In`. Её композиция — категория с точностью до изоморфизмов
носителя; её область — расслоение по ключу со сменой вверх копределом по слою; её слово —
полурешётка с поглощающим нулём прекращения; её область определённости — restriction-категория;
её незнание — обитаемая клетка выхода и обязанность ослепнуть на прячущей букве; её время — буква
входа; её выход в мир — функтор, различённый линейностью ресурса; её предъявимость — финальность,
свидетель которой обязан доказать зрячесть.

Сверх `S × In → S × Out` не введено ничего.
