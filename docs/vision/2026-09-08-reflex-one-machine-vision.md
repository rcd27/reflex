# Reflex: одна машина

*Канон. 2026-09-08. Заменяет собой шесть предыдущих vision-документов.*

## Зачем этот документ один

Шесть документов росли слоями, и каждый добавлял словарь. Слои
множились, а предмет под ними оказался один — и давно названный наукой.
Смотришь в код: шесть подписей одной машины, четыре словаря одной
области, шестьдесят с лишним повторов одной мысли о незнании. Мы не
изобретали — мы переоткрывали, каждый раз заново и под новым именем,
конструкции, доказанные до нас.

Этот документ не толкает телегу сильнее. Он ставит её на колёса:
объявляет **единственный объект** и выводит из него всё, чем reflex
занят, ссылаясь на готовую математику там, где она есть, и на замер
дерева там, где имя нужно оплатить. Наружу торчит **один синтаксис
движка**; всё выше него — не дописано, а выведено, и потому замкнуто.

Правило замера держится на всём протяжении: **прежде чем назвать
конструкцию отсутствующей — грепнуть.** Числа ниже намерены по дереву на
2026-09-08, а не переписаны из прежних документов; где мера грубее
прежней, это сказано.

## Центральный тезис

> **Объект reflex — машина Мили как значение. Всё остальное — её
> коалгебра, её категория, её расслоение, её функтор в мир. Ничего сверх
> этого не вводится.**

```
Step:  S × In → S × Out
```

Одиннадцать разделов — следствия одной строки. Двенадцатый говорит, чего
эта строка не покрывает, и что из прежних шести отменено поимённо.

---

## 1. Объект: машина Мили есть коалгебра

Морфизм reflex построен и стоит в `core/src/step.rs:24`:

```rust
pub trait Step: Sized {
    type From;
    type To: crate::word::Word;   // СЛОВО: адресовано области
    type Notes;                   // ПОКАЗАНИЯ: копятся вбок
    fn step(self, input: Self::From) -> (Self, Self::To, Self::Notes);
}
```

Состояние входит и выходит **значением** (`self`, не `&mut self`):
цепочку можно скопировать, отложить, прогнать заново. Это не стилевой
выбор — это условие §10.

**Имя из науки.** `step: S × In → S × Out` каррируется в

```
β : S → (S × Out)^In
```

— это **коалгебра** эндофунктора `F(S) = (S × Out)^In` на категории
алфавитов (Rutten, *Universal coalgebra: a theory of systems*, 2000).
Детерминированный автомат — коалгебра; машина Мили — её вариант с
выходом на переходе. Финальная коалгебра `F` — каузальные потоковые
функции; поведение машины есть её образ в финальной коалгебре. Отсюда
прямо следует §10: «предъявить шаг» = «взять его образ в финальной
коалгебре», а `replays` — бисимуляция.

Домен просил не *строить* цепочку (это алгебра композиции, §3), а
*разбирать её обратно* — наблюдать состояние, возвращаться от выхода к
причине. Наблюдение — ко-сторона построения. Оттого «ко-»: reflex живёт
на коалгебре, и это не метафора, а тип в `step.rs`.

**Замер: шесть подписей свелись к одной, и это уже случилось.** Прежний
документ насчитал машину Мили, записанную шестью несовместимыми
подписями. На 2026-09-08 подавляющая часть реализаций `Step` уже несёт
**единую трёхвыходную форму** `(Self, To, Notes)` — весь `instrument`
(`detect`, `drift`, `leg`, `fate`, `pace`, `sag`, …), `detector` (семь
impl), `timeout`, `debounce`, `tls::assembly`, `engine::lib`,
`engine::row`, `flow_table`. Сведение произошло; документ его фиксирует,
а не назначает.

Остаются **вне** этой подписи ровно те места, что и должны (§9):

| подпись | где | почему вне |
|---|---|---|
| `serve<F>(…)` | `core/src/serves.rs`, `linux/.../terminal.rs` | это **драйвер**, не морфизм |
| `handle(&mut, pkt) -> (NfqVerdict, Vec)` | `linux/.../pipeline.rs:115`, бинарь очереди | **вытягивание** — иной носитель (§9.4) |
| `feed(&mut, wire, now) -> Fed` | `engine-nfq/src/plane.rs:286` | то же вытягивание |
| свободная `step(look_up, …) -> Stepped` | `engine/src/step.rs:29` | то же |

Первая строка законна навсегда. Три нижние — единственный незамкнутый
шов reflex, и §9.4 называет его причиной.

## 2. Замкнутость по влиянию: две двери, третьей нет

> **Войти в шаг можно только буквой входного алфавита; выйти — только
> словом или показанием.**

Ни скрытых часов, ни `Reader`, ни глобального знания. Всё
недетерминированное **прибывает буквой** или не прибывает вовсе.
`FnMut` запрещён не за некрасивость — он и есть незаписанный вход,
спрятанный в замыкании (`step.rs`, докблок «почему машина Мили, а не
функция»).

**Полнота делает проверку типов честной.** Будь алфавит частичным —
окажись хоть одна встречаемая буква непредставимой, — шаг прошёл бы
типизацию и всё равно встретил в бою то, чего не объявлял. Полнота
значит:

```
Собралось(f)  ⇒  ∀ буква b, которую f может встретить:  b ∈ In(f)
```

Вот зачем строился полный входной алфавит (`core::detector::DetectorEvent`
= `Packet | Opaque | Tick`); учёт в бою был следствием, не целью.

**Замер.** `.await` — прямая улика чужого носителя (§9). На 2026-09-08:

```
core 5 · runtime 4 · linux 4   — драйверы, им можно
engine 0 · engine-nfq 0 · instrument 0 · os 0   — морфизм в поток не заходит
```

Морфизм чист; недетерминизм живёт в драйвере, за дверью буквы.

## 3. Композиция: категория с тождеством

Соединение двух шагов сверяет алфавиты, и сверку делает компилятор
(`step.rs:86`):

```rust
impl<A: Step, B: Step<From = A::To>> Step for Then<A, B>
```

`B∘A` определено ⟺ `A::To = B::From`. Аксиомы категории:

```
(h∘g)∘f = h∘(g∘f)          ассоциативность — тривиальна для цепочек-методов
id∘f = f = f∘id            тождество — Id<T>, step.rs:118
```

`Id` не украшение: без него композиция — полугруппа, а не категория, и
необязательное звено (выключенное настройкой) пришлось бы выражать
особым случаем у вызывающего, а не той же алгеброй.

**Показания складываются произведением, а не общим словарём**
(`type Notes = (A::Notes, B::Notes)`): два звена не обязаны говорить на
одном языке, чтобы их показания сложились, и позиция в кортеже называет
автора вернее метки. Это несущая деталь §11: показания идут **вбок**,
сосед их не ест — иначе `B: Step<From=A::To>` заставила бы читать
сказанное не ему.

Рядом стоит `Alongside` (`step.rs:194`) — «два звена слушают одну букву,
говорит один»: не конвейер, а параллельное наблюдение с одним словом
наружу.

## 4. Область: расслоение по ключу

Слово адресовано **области**, и области упорядочены охватом:

```
Packet  ⊂  Conversation  ⊂  Target
пакет   ⊂  разговор       ⊂  цель
```

> **Перейти из узкой области в широкую нельзя иначе, чем собрав узкое по
> ключу.** Разговор — пакеты, сложенные по пятёрке; цель — разговоры,
> сложенные по адресу. Ключ и есть то, чем область расслаивается.

**Имя из науки.** Это **расслоение** (fibration) Гротендика над базой
охвата: проекция `p: E → B`, где база `B` — решётка областей, а слой над
областью `R` индексирован её ключом `R::Key`. Смена области **вверх** —
левый Кан вдоль проекции ключа, то есть копредел по слою:

```
Conversation  ≅  ∐_{k : Flow}  Packet
Target        ≅  ∐_{k : Addr}  Conversation
```

Отсюда ответ на вопрос, который мучил прежние редакции («как ключ попадает
в тип»): **никак — он там уже есть.** Ключ не параметр цепочки, он
**принадлежит области**, потому что смена области без него невозможна.
Недостающая строка — одна:

```rust
pub trait Region {
    type Key: Eq + Hash;   // Packet::Key = ()  Conversation::Key = Flow  Target::Key = TargetKey<N>
}
```

**Уточнено 09.09.2026 по дереву.** `trait Region` в коде НЕТ вовсе — ключ
области объявлен как `Base::Fibre` (`core/src/word.rs:36`), и объявлен давно:
`Packet` → `()`, `Conversation` → `Flow`, `Target` → ключ цели. Пустого трейта,
которого ждала прежняя редакция, не существует.

Но замер ниже верен буквально: **объявлено и не взято.** Вне собственного
объявления `Fibre` не читается ни одним потребителем — только как `= ()` в
тестах; а `FlowTable`, уже обобщённая по ключу, получает его от ВЫЗЫВАЮЩЕГО, а
не из области. Недостающая строка — не объявление ключа, а его СВЯЗЬ с
носителем семьи (§12.1).

**Ключ цели сам расслоён — уточнено 09.09.2026 по коду, обогнавшему эту
строку.** Прежняя редакция писала `Target::Key = IpAddr`, но `engine/src/row.rs`
уже знает иное: `TargetKey { Named(N) | Unnamed(Addr) }`, потому что имя есть не
всегда (`Awaited ⊑ Silent ⊑ Spoken`, §5). Адрес — не ключ цели, а его нижний
слой: тот, что остаётся, когда цепочка имени не дала.

И это не изъян, а та же замкнутость по влиянию (§2), только на ключе:
**потребитель не может ключевать тем, чего вышестоящая цепочка не различает.**
Не стоял `extract(Sni)` — имени нет ни у кого ниже по пайпу, и ключ цели
вырождается в адрес по построению, а не по недосмотру. Ключевание пропадает из
речи ровно потому, что оно выведено из того, что цепочка умеет различать.

**Область ставит носителю ПОТОЛОК.** Не выбирает — ограничивает: ядро
дотягивается до `Flow` (conntrack ведёт запись на каждый разговор) и до
`Unnamed(Addr)` (nftables-набор переживает потоки и читается правилом на wire
speed); до `Named` не дотянется никогда — ядро имён не знает и знать не может.
В пределах потолка носителя выбирает драйвер (§9), и выбор этот не единственный:
сегодня по одному и тому же ключу `Flow` состояние живёт и в `ct mark`, и в
`FlowTable` фасада.

Это сосуществование — **не роль, а отложенный дубль**: `Flow` ядру доступен, что
и доказано ct-краем, значит юзерспейсная таблица держит по нему второе понимание
того же предмета (§12.1, `one-subject-one-law`) и ждёт решения о переезде. Сам
ТИП `FlowTable` при этом нужен дальше и по другой причине: областям, чьи ключи
ядру недоступны (`Named`, а при отсутствии набора и `Unnamed`), юзерспейсный
носитель необходим, и там таблица обобщится по ключу.

Первое воплощение проверено боем 09.09.2026: состояние автомата по ключу `Flow`
живёт в `ct mark`, юзерспейс zero-state, девятый закон (`certify::remembering`)
держится на живом ядре. Спека — `docs/superpowers/specs/2026-09-09-conntrack-state-edge-design.md`.

**Следствие для синтаксиса — ради него всё:** ключевание **пропадает из
речи**. Не спрятано — выведено. Область объявлена источником (`from(TCP)`
— разговор, `from(IP)` — пакет), ключ определён областью, расслоение
построено фреймворком один раз. Потребитель ключа не пишет.

**Замер.** `plane.rs` держит **девять** карт по ключу
(`plans`, `cursors`, `seen_at`, `targets`, `flow_names`, `named`, …).
Именованное же расслоение — `DetectPer`, `FlowTable`, `group_by_flow` —
**вне своего крейта не употреблено ни разу**: за пределами `core`
встречается только в тестах `core`. Расслоение написано и не взято —
потому что носитель не тот (§9.4). Разрыв не в алгебре.

**Машина, держащая два ключа, — это две машины.** Морфизм по построению
работает с одним ключом и о других не знает; сколько их и как долго они
живут — заявляет драйвер. Неограниченный ключ есть неограниченная память,
и потому срок жизни ключа обязан быть объявлен, а не подразумеваться.

## 5. Слово: полурешётка с поглощающим нулём

Слова одной области сводятся, и у сведения есть **поглощающий элемент**.

> **Ноль произведения — это прекращение, а не широта.** Слово, кончающее
> предмет, поглощает всякое слово о том, как его вести. «Больше не ведут»
> старше «ведут так-то», в какой бы области ни было сказано.

**Имя из науки.** `(Words, ⊓)` — полурешётка сведения (join-semilattice);
прекращение `⊥` — её **absorbing / zero element**:

```
∀ w :   stop ⊓ w = stop
```

Охват — **ортогональная** ось: он управляет не силой, а **направлением**
спуска, и это типом проверяется (`core/src/word.rs:469,529`):

```rust
pub trait Within<Wider: Region>: Region {}          // Packet ⊂ Conversation ⊂ Target
pub trait Descends<Into: Word>: Word
where Into::Of: Within<Self::Of> {                  // спуск только ВНИЗ по охвату
    fn descends(self) -> Into;
}
```

Баунд `Into::Of: Within<Self::Of>` разрешает `Order@Conversation →
Verdict@Packet` и **не собирает** обратное: слово пакета не станет словом
цели. Отказ проверен причиной, отдельной сборкой:
`the trait bound Conversation: Within<Packet> is not satisfied`.

Промолчать умеет **только прекращающее слово** — несущая деталь: спуск
идёт в `Option<Act>`, а не в `Act`. Одень «обычная жизнь разговора» в
какой-нибудь `Act::Pass` — и молчание, обретя слово, выиграло бы
произведение у плана цели. Транзитивность (`Packet: Within<Target>`)
пишется рукой: баунд на транзитивном замыкании система типов не выражает,
а спуск через уровень в бою есть — план цели решает судьбу пакета, не
спрашивая разговора.

**Открыто (§12.2): сведение.** `Within`/`Descends` построены и
проверены. Кто **выбирает** между спущенными словами — сегодня
`unwrap_or_else` у места вызова (`engine/src/step.rs`, «приказ старше
плана»): верно по существу, законом не названо, в другом месте будет
написано иначе.

## 6. Область определённости: restriction-категория

«Спросить у живой цепочки, где ты, не двигая её» — не наша выдумка.

**Имя из науки.** **Restriction category** (Cockett & Lack, *Restriction
categories I*, 2002): каждому морфизму `f` сопоставлен идемпотент `f̄` —
его область определённости, вычислимая **не выполняя `f`**. Несущая
аксиома:

```
f ∘ f̄ = f          проверка готовности ничего не меняет
```

— она и разрешает спрашивать готовность в любой момент. Отсюда `guard` /
`ready()` и выходной алфавит

```
StepOutcome { Advanced, NotReady, Failed }   «не готов» ≠ «сломан»
```

и закон уровня: **корректность никогда не зависит от события; событие
покупает только латентность.** Отсюда же `optional` как `f ⊔ id` —
необязательное звено выражено той же алгеброй (§3), а не особым случаем.

## 7. Незнание: обитаемая клетка выходного алфавита

Выходной алфавит **тотален** и содержит клетку «не наблюдал» — отдельную
от «наблюдал пустоту».

```
Told    { Nothing, Blind }          «события не было» ≠ «мы не смотрели»
Served  { Answered, Idle, Blind }   «не было работы»  ≠ «ждать не на чем»
Sight   { Full, Partial }           своя слепота названа числом
Verdict { Held, Broken, Invalid }   «нарушил»         ≠ «стенд не смог»
```

**Замер: закон уже действовал и не был назван.** Идиомы незнания густо
рассыпаны по дереву (грубым грепом по `.rs`, 2026-09-08):

| идиома | вхождений |
|---|---|
| «неотличимо» | 76 |
| «молча» / «тишина» — расхождение без свидетеля | 564 |
| «свидетель» | 135 |
| «величина», а не тишина | 110 |

Цена отсутствия клетки названа в коде числом: алфавит без клетки «не
смог» превращает **собственный** дефект прибора в улику против мира.
Это не эстетика — это класс ошибки, и §12 держит ему место четвёртым
классом («не установлено»: не успех, не ошибка, не несовместимость —
отсутствие наблюдения).

## 8. Время: буква входа, а не измерение

Прежние документы спорили, время — измерение категории или её контекст.
Ответ **третий**: ни то ни другое.

> **Время — буква входного алфавита.**

`In ⊇ { Tick }`; морфизм остаётся чистой функцией `(S, событие) → (S,
слово, показание)`, часов у него нет, `.every(100.ms)` выражается сеткой,
а не сном. Механизм построен и подключён (`core/src/interleave.rs`):
сводит пакеты и узлы сетки в один **монотонный** поток букв, выдаёт
сперва перешагнутые узлы и лишь потом сам пакет — «детектор, увидевший
пакет раньше закрытия окна, отнёс бы его байты не к тому окну». Есть тест
шва (`engine-nfq/tests/unread_feeds_the_seam.rs`).

Отсюда **одна точка входа в машину** вместо двух — и исчезает гонка,
которую сегодня держит `Mutex` там, где в плоскость пишут два потока
(горячий путь и тред часов), а чередование их нигде не записано.
Прогнать заново нечего, пока последовательности не существует, — это
прямо связывает §8 с §10.

## 9. Мир: функтор из морфизма в драйвер

Морфизм не касается мира сам — его в мир **вносит функтор**, и функторов
несколько. Различаются они не платформой, а **линейностью ресурса**
(`core/src/backend.rs`, `serves.rs`):

| носитель | линейность | обязательство |
|---|---|---|
| `Source` (`backend.rs:42`) | копия | наблюдение **без** ответа |
| `Sink` (`backend.rs:55`) | вброс | добавить в сеть |
| `Serves` (`serves.rs:65`) | владение | **обязан** ответить удержанному |

Мониторинг не отвечает никогда, inline-фильтр отвечает всегда — это выбор
**домена**, а бэкенд ему следует. Это закрывает старый открытый вопрос
«как выразить семантику бэкендов»: она выразилась **двумя входами**, а не
богатым функтором над одним.

### 9.1. Способности: что образ функтора допускает

Бэкенд объявляет не список глаголов, а **область, которую даёт держать**,
и слово к ней:

```rust
trait Backend { type Holds: Region; type Verdict: Word<Of = Self::Holds>; }
```

Способности `Can*` (`core/src/capability.rs`: `CanHold`, `CanRefuse`,
`CanMark`, `CanRewrite`, `CanSever`, …) — пять слов об одном: «пакет в
руках». Цепочка со словом `w` собирается над бэкендом `B` ⟺ область `w`
покрыта `B::Holds` и `w` лежит в образе способностей `B`. Слово `Sever`
**не соберётся** над бэкендом без `CanSever`.

**Замер — вот он, разрыв.** Боевой `engine-nfq` не употребляет **ни одной
способности** (0 вхождений). Compile-time контроль, обещанный прежними
документами, построен (`capability.rs`) и **не подключён к пути, по
которому ходят пакеты**: продукт говорит на алфавите `NfqVerdict`, а не
способностей.

**Гейт стоит на АКТЕ, а не на цепочке** (09.09.2026). Требование
способности живёт там, где акт СОЗДАЁТСЯ, и требуется ровно та, которой
этот акт пользуется: наблюдение — ничего сверх удержания, обрыв —
`CanSever`, вопрос — `CanAsk`. Пока требование стояло на цепочке (`emit`
просил три способности разом), следствий было два, оба плохих: носитель,
умеющий только смотреть, не собирался даже под наблюдением, а носитель с
формальным «спрашивать нечем» пропускал `Ask` — цепочка собиралась и молча
уходила ждать ответа, которого никто не пошлёт. Рантайм-выбор потребителя
при этом цел: гейт на конструкторе, а не на ветке.

**Способность, чей метод возвращает `None` КОНСТАНТНО для данного
носителя, не заявляется**: константный `None` — не ответ, а заглушка, и
заявленная способность становится обещанием, которое никогда не
исполняется. `None`, зависящий от входа, — законный рантайм и остаётся
(`CanSever::notice`: у датаграммы нет формы обрыва — свойство ПАКЕТА).
Отказ на сборке узнаёт то же, что рантайм-`None`, но раньше и громче:
несобирающаяся цепочка вместо молча ждущей. Оплачено снятием
`impl CanAsk for NfqueueBackend`, где `None` был константен.

### 9.2. Подъём — один из функторов

`Over<S, K>` (`step.rs:346`) поднимает морфизм в поток
(`futures::Stream`): одна машина на весь поток, `Item = (K::To,
K::Notes)` — пара наружу. Функтор идёт **только вверх** и стену образует
**конкурентность, а не время**: `switch_map` запускает работу параллельно
потоку, у шага же второй нити нет. Оттого расследование нельзя поставить
в горячий путь — не потому что подпись не берёт `Future`, а потому что
оператора, которым оно выражается, здесь нет вовсе. `Stream` тем самым
понижен в звании: из носителя категории (как было в реактивной редакции)
в **один из драйверов**.

### 9.3. Тишина обязана доходить

`Serves` зовёт решение только на букве, несущей пакет, — и приборы
простоя, тишины, троттлинга видят свой предмет **только в тишине**, а
через этот драйвер тишина до них не доходит. Разрешение (спроектировано,
§12): машина шагает **на каждой** букве `Packet | Tick`; ответ отдаётся
там, где есть кому отвечать. Ответ — функция **буквы**, не машины
(`Reply { Answered, Silent }`); шов держит драйвер, а не морфизм.

### 9.4. Пропавший функтор — это `match` на краю, и это весь разрыв

Носитель фундамента — значение (`Step`); носитель боевого движка —
**вытягивание** (`handle`/`feed`: подать пакет, ждать вердикт на
возврате). Оттого построенное неприменимо буквально, а не по недосмотру:
поточный `DetectPer` в синхронный `handle` не встаёт физически.

Три алфавита вердикта на одни четыре слова (`NfqVerdict`,
`NfqVerdictKind`, `Answer`) — три перевода `match` там, где должен стоять
**один функтор**: доменный акт → слово носителя через способность.

```
Act::Pass  → CanHold::release()      Act::Drop   → CanRefuse::refuse()
Act::Marked→ CanMark::mark()         Act::Sever  → CanRefuse + CanSever + CanInject
```

`NfqVerdictKind` при этом сливает пометку с пропуском — 64-й случай
«неотличимо». Замкнуть движок = провести этот функтор и снести
`NfqVerdict`/`NfqVerdictKind` (§12.4).

## 10. Предъявимость: финальность и её свидетель

Семь законов эталона (`core/src/certify/*`) свидетельствуют **эффект**:
команда построена — вышла ли на провод; все семь спрашивают «мир принял?».
Восьмой отвечает на второй конец: **«решение восстановимо?»**

**Имя из науки.** Записанная лента букв `[b₁…bₙ]` плюс начальное `S₀`,
прогнанная, даёт на каждом шаге четвёрку `(S_до, in, S_после, out)` — и
это **и есть** цепь причин: происхождение не несут на горячем пути, оно
**восстанавливается**. «Два прогона одной записи согласны» = морфизм
**детерминирован по объявленному алфавиту** = его образ в финальной
коалгебре определён; сверка = **бисимуляция**.

```rust
trait Recording<In> { fn inputs(&self) -> Vec<In>; }   // независимая запись
trait CanReplay: Step { fn seed() -> Self; }           // предмет — семя S₀

enum Broken {
    Unstable  { … },   // два прогона разошлись → недетерминизм ВНУТРИ: скрытый вход
    Diverged  { … },   // прогоны согласны, расходятся с боем → объявить вход
    Entangled { key },  // один ключ течёт, все сходятся → две машины на одном ключе
}
enum Invalid { NoRecording, NoSeed, Incomplete { … } }  // беда стенда, не подопытного
```

`Entangled` делает закон §4 («две машины») **механически проверяемым**:
правило, которое надо было помнить, становится прогоном, который краснеет.
`replays` — **единственный** из восьми законов, которому не нужны ни
стенд, ни root, ни ядро, ни сеть: его свидетель — независимая запись,
годная в CI. И запись эта **не есть запись трафика**: `grep 'payload\['`
по движку пуст — читаются `.len()`, `.is_empty()`, форма заголовка;
порядка двух десятков байт на пакет, ноль пользовательского содержимого.

**Статус: построен и предъявлен на живом трафике** (09.09.2026). Движок
пишет окно СВОЕЙ ленты (`.certifying()`), набрав его — пере-подаёт свежей
семье машин дважды и сверяет не ленту, а сказанное. Боевой прогон на
реальном ТСПУ: четыре окна по 64–80 букв воспроизведены, лента при этом
несла настоящий тихий дроп, а не синтетику.

Буква ленты несёт **адрес** (`To { One, Each, Nobody }`): в живом прогоне
«чья она» знает разбор, на переигровке разбора нет — лента есть весь вход.
Три адреса, не «ключ либо его нет»: у узла сетки ключа нет по существу
(время идёт всем), у непонятого — потому что взять неоткуда.

**Ответ закона знает клетку «свидетельства нет»** (`Replayed::Silent`), и
она оплачена ошибкой: окно из одних узлов сетки без живых машин
«воспроизводилось» тривиально — пустое равно пустому, — и под этим
вердиктом прошла мутация, которую стенд обязан был поймать. Согласие двух
молчаний **не есть** воспроизводимость; клетка живёт в ЯДРЕ закона, ибо
вызывающий, глотающий пустоту молча, прячет ровно тот класс, ради которого
закон и построен (§7 — незнание обитаемо).

Отсюда же дисциплина ПРИЁМКИ: стенд доказывает, что умеет краснеть,
ПРЕЖДЕ чем свидетельствует зелёным. Мутант (прибор со скрытым входом)
включается переменной среды, и оба прогона идут подряд.

## 11. Наружу — один синтаксис

Всё выше — внутреннее. Публичный контракт reflex **один**:

```rust
fn main() -> Report {
    engine(Nfqueue::queue(200))       // НОСИТЕЛЬ — голова цепочки
        .from(Tcp)                    // транспорт: свой словарь провода и свой порт
        .extract(Sni)                 // чем ключуется цель
        .detect(Retransmit::unanswered())
        .detect(Silence::after(secs(5)))
        .on(|target, distress| { … }) // НАБЛЮДАТЬ; `.act` — ДЕЙСТВОВАТЬ
        .run()
}
```

*Раздел переписан 10.09.2026: прежняя редакция описывала эскиз (`engine(Backend, from(TCP))`,
`.filter`, `.route`, `notes.wire(…).await`), который никогда не строился — ни одного его имени в
дереве нет. Ниже — контракт, вышедший наружу, и ответ на довод прежней редакции против терминатора.*

**Выражение, а не строитель.** У строителя `.to(A)` и `.to(B)` переставимы — это регистрации.
Здесь порядок несёт смысл, потому что композиция **есть проводка влияния** (§3), и бессмысленная
перестановка **не собирается**: прибор чужого алфавита в пайп не встанет (`IntoProbe<Wide<Wire>>`),
второй писатель марки не встанет за первым (`Home = MarkSilent`), а свёртка без реакции не
соберётся вовсе (`Folding` без `.on_target`). Проверяет это тип, а не дисциплина зовущего.

**Носитель — голова, а не второй аргумент.** `engine(X)` называет НОСИТЕЛЯ, и всё ниже первой
строки от него не зависит: цепочка, транспорты, приборы, цикл переносимы. Это предъявлено
прогоном — фасад собирается под `x86_64-pc-windows-msvc`, и `engine(WinDivert::filter(…))` встаёт
в ту же дверь. Разница между платформами — одна первая строка.

**Три оси полиморфизма и ОБЛАСТЬ поперёк них.** `.from(T)` — транспорт, `.detect(D)` — прибор,
терминал — наблюдать (`.on`) или действовать (`.act`). Поперёк стоит область, о которой сказано:
`.on` слышит слова РАЗГОВОРОВ, а пара `.about(свёртка).on_target(реакция)` — слово о ЦЕЛИ (§4,
`Target ≅ ∐ Conversation`). Пара держится типом: свернул — обязан сказать.

**Терминал — не чёрный ход, а место, где называется линейность.** Прежняя редакция возражала:
«`.run()` не нужен, прогон есть потребление потока; терминатор вернул бы строителя через чёрный
ход и снова сделал конец цепочки особым местом». Возражение снято тремя доводами, и каждый
проверяем.

*Первое.* Потока показаний нет и не может быть без рантайма у ПОТРЕБИТЕЛЯ: `notes.wire(…).await`
требует исполнителя там, где его нет. §9.2 понизил `Stream` до одного из драйверов, а замер §2
показывает `.await` = 0 в крейтах морфизма. Синхронная петля — не уступка, а следствие.

*Второе.* `Report` — не строитель, а ЗНАЧЕНИЕ несостоявшегося запуска: «не начался, вот причина»
(§7, обитаемая клетка). Отказ мира есть знание, а не запись в журнал; `fn main() -> Report`
потребляет его через `Termination`. Строителя через терминал не вернуть — из `Report` цепочку не
достать.

*Третье.* Конец цепочки ДЕЙСТВИТЕЛЬНО особое место, и это закон, а не уступка: выбор `.on` против
`.act` есть выбор ЛИНЕЙНОСТИ ресурса (§9), и там же стоит гейт способности (§9.1) — акт требует
ровно той способности, которой пользуется, в точке создания. Особость конца выведена, а не введена.

**Цена, названная вслух.** Реакция приходит замыканием, а не значением; §10 сверяет слова машины
(`Said`), но не то, что потребитель с ними сделал. Поток показаний был бы в этом сильнее — его
можно записать и сравнить. Сегодня это предел, а не дефект: замыкание живёт в ДРАЙВЕРЕ, где
`FnMut` законен (§2 запрещает его морфизму, не циклу).

**Замыкание.** Ключ выведен областью (§4), а не написан; слово адресовано типом (§5), а не
комментарием; готовность спрашивается идемпотентом (§6), незнание обитаемо (§7), время — буква
(§8), мир — функтор (§9), восстановимость — прогон (§10). Наружу торчит **только** `engine(…)`:
внутренним именам незачем — и это проверяется грепом, а не обещанием.

**Заготовки — нашими же кирпичами.** `Silence`, `Retransmit`, `SynDrop`, `DnsPoison` — поставка
фреймворка, но **не чёрный ящик**: тот же входной алфавит, та же пара на выходе, тот же адрес
слова, та же область. Свой прибор встаёт той же дверью (`own`) и говорит СВОИМ словом — парк
вкладывается в словарь потребителя, а не наоборот. Заготовка, которой понадобилось нарушить
закон, — не заготовка, а находка: значит закон неполон, и чинить надо закон.

## 12. Чего строка не покрывает, и что отменено

### Открытое, по убыванию веса

- **12.1. Связь ключа с носителем.** Ключ объявлен (`Base::Fibre`) и не взят:
  `FlowTable` берёт его от вызывающего. Ключ принадлежит
  области (§4) — это недостающая строка и первый шаг замыкания. За ней:
  `FlowTable` обобщается по ключу и становится `Step`, `Plane` берёт её —
  расслоению даётся первый боевой потребитель, число карт падает.
- **12.2. Сведение спущенных слов.** `Descends` построен, направление
  проверено охватом. Кто **выбирает** между спущенными словами — законом
  не назван (§5).
- **12.3. Восьмой закон `replays`. ЗАКРЫТО** (09.09.2026): построен,
  предъявлен на боевой ленте, стенд доказывает свою зрячесть мутантом.
  Осталась одна открытая грань — лента ЧЕРЕЗ ПРОЦЕСС: `Instant` не
  переносится, и запись, пережившая процесс, требует другой буквы времени
  (§8-масштаба). Сейчас закон предъявляется внутри прогона.
- **12.4. Замыкание движка. ЗАКРЫТО** (10.09.2026): функтор носителя доведён
  до фасада — цикл говорит с миром через `Serves`/`Terminal`/способности, дубль
  таблицы вердикта умер по построению, шов (`interleave`) потреблён впервые с
  постройки, тишина доходит. Носитель стал ПАРАМЕТРОМ: `grep reflex_linux
  reflex/src/lib.rs` = 0 (кроме докблока, объясняющего сам замер), фасад
  собирается под `x86_64-pc-windows-msvc`, и второй носитель (WinDivert) встаёт
  в ту же дверь. Осталось НЕ закрытым: `NfqVerdict`/`NfqVerdictKind` живы на
  втором пути A/B — он держится как независимый свидетель, и снос его есть
  отдельное решение, а не долг этой работы.
- **12.5. Наряд на работу из алфавита.** Цепочке нужен только
  `ClientHello` — движок обязан жечь процессор только на нём. Состояние,
  которого не завели, чистить не надо; половина задачи об уборке исчезает.
- **12.6. Область объявляет свою смерть?** Уборка выводится из входного
  алфавита: TCP — по букве, UDP/QUIC — по сроку, без часов — по ёмкости.
  Свойство той же области, что владеет ключом (§4). Если `Region` называет
  `Key`, ему же, похоже, принадлежит и закон смерти.
- **12.7. Четвёртая ось.** Паспорт прибора (`instrument/src/lib.rs`)
  объявляет оси, из которых `Shape { Quantity, State, Event, Verdict,
  Series }` не сведён: он говорит, какие операторы законны над выходом
  (переход осмыслен на состоянии, бессмыслен на величине). Свойство
  алфавита или отдельная ось — не закрыто. **Правило дописывания:** новая
  ось входит, лишь **предъявив замер, который без неё не объясняется.**

### Чего категория не моделирует (названо, чтобы не предлагали заново)

- **Роли участника сети.** Домен симметричен относительно отправителя и
  получателя; асимметрия живёт в социально-правовой надстройке, не в
  протоколе. Типовая параметризация ролью — метка, а не свойство:
  параллельная категория с инвертированным параметром получается
  механически и изоморфна исходной. Категорных средств защиты от
  двойного применения не существует; это не дефект, а следствие
  категорной чистоты.
- **Ценность цели, легитимность применения, стратегии обхода чего-либо.**
  Это значения, которые пользователь передаёт в операторы, не часть
  фреймворка.
- **Системная беда как часть домена** — но её **отказ** моделируется:
  `Refused { why }` есть знание, а не шум.

## Резюме

Объект reflex — **машина Мили как значение**, то есть коалгебра. Её
композиция — категория с тождеством; её область — расслоение по ключу;
её слово — полурешётка с поглощающим нулём прекращения; её область
определённости — restriction-категория; её незнание — обитаемая клетка
выходного алфавита; её время — буква входа; её выход в мир — функтор,
различённый линейностью ресурса; её предъявимость — финальность,
свидетельствуемая независимой записью.

Ничего сверх строки `S × In → S × Out` не введено. Всё выведено, и
потому фреймворк замкнут сам на себя. Наружу торчит один синтаксис:
`engine(Backend, from(…).…)`. Что осталось — не достроить теорию, а
провести один функтор на краю (§12.4) и назвать один ключ (§12.1); обе
работы измеримы числом, и число ждёт.
